# Roadmap（编排核心）

> **回答什么问题**：现在做到哪、下一步做什么、按什么顺序、每个切片的范围边界在哪。
> **读者**：全员 · 新人第三份 · 产品 / 技术负责人　**长度上限**：4 页
> **不写什么**：产品意图与成功指标（`docs/overview.md`）、单条需求的完成度与验收标准（各 `specs/NNN-xxx/spec.md` 与 `tests/`）、技术阈值（`docs/nfr.md`）、决策理由（`docs/adr/`）、已交付的变更记录（`CHANGELOG.md`）、术语（`docs/glossary.md`）。

全项目唯一**编排与状态**归属地。纯文本表格 + 双向回链，`grep` 就能拉出整条脉络，不依赖任何工具。新人读完 `README.md` → `docs/architecture.md` → 本文件，应当能说清「边界在哪、现在做到哪、下一步是什么」。

---

## 1. 使用规则

1. **roadmap 先改，再改 spec**。范围变了先改本表那一行，再动受影响的子 spec；顺序反了，本表就退化成事后记录。
2. ID 用 `S<n>`（slice），不用 `R<n>`：`R` 前缀已被风险登记占用，同一个 `R3` 会指两样东西。
3. **ID 不可变**。`S3` 一旦被引用就不得修改、删除或复用。作废条目只把状态改成 `cancelled`，**保留行与理由**。
4. 子 spec 在自己的 `spec.md` 头部 `Input` 行写 `Parent roadmap → entry <ID>`，形成双向链；编排状态与本表不一致时以本表为准，并立即修正子 spec。
5. **两种状态不要混**：本表的状态是**编排状态**（排没排、在不在途）。功能**是否验收以 `tests/` 与代码为准**，不在本表写「实现了百分之几」「哪几条 FR 完成了」——那是 spec 与测试的事，抄进来就变成第二份真相源。
6. **不给没触发条件的事建行**。条件未出现的演进方向放 §5，不占 ID、不留空行：明确排除的东西进表只会制造假进度。
7. **交付过程不写进本表**。逐批进度、跟改登记、收口核销属于 `CHANGELOG.md` 与提交历史；本表只留交付后的终态和下一步。

## 2. 状态定义

| 状态 | 判定 |
| --- | --- |
| `planned` | 已排期、未开工，范围边界已写清 |
| `in_progress` | spec 已批准，实现或验收中 |
| `delivered` | 交付附注已落地，验收在 `tests/` 里 |
| `deferred` | 明确推迟；**必须写出等什么条件**，不写「以后再说」 |
| `cancelled` | 作废，保留行与理由，ID 不复用 |

状态改 `delivered` 前先跑 `pnpm test`。「表已建、索引已加、外键已加」不算实现入口。

## 5. 切片顺序与不建条目的方向

顺序不是按工作量排，是按**「不做会不会堵住后面的路」**排。

1. **`S4` 是主线**：谱书编目与成品排版是第一批有真实消费方的能力。在它落地前，`docs/nfr.md` 里的呈现与导出类阈值只是重构验收条件，不是被测对象的行为承诺。
2. **`S7` 不阻塞开发，但阻塞「敢对外承诺可用性」**：成本低，收益是把「不知道挂没挂」变成「知道」；§4 的两项上线前演练挂在这里。
3. **`S3` 只补状态，不加新范围**：deferred 那批格式能力的取舍理由在 `docs/overview.md`，翻案先改 overview。

**不建条目的方向**（触发条件出现才建行，不预留 ID）：

| 方向 | 触发条件 |
| --- | --- |
| 编辑锁 | 出现真实并发覆盖投诉 |
| 缓存层、外部搜索索引、服务端分页 | 单谱系人丁量级或全量加载成为实测瓶颈 |
| 多实例化（共享限流、后台任务） | 单实例承载不住流量，或限流被证明必须真正生效 |
| 拆服务 / 消息队列 | 团队规模与 QPS 同时越过拆分门槛 |
| 审计通道 | 有明确合规诉求（谁要、保留多久、能否篡改） |

最后一条尤其要忍住：诉求不明就做，大概率是一张没人查的表。

开放问题（字辈分支、女儿入谱子女归属、联宗、导出自助化、指标埋点口径）在 `docs/overview.md`，不在本表造条目；它们改变的是范围边界，定了之后先改 overview 与本表对应行。

## 6. 追溯与核对

```bash
# 从条目 ID 拉到本表行
grep -n "S4" docs/roadmap.md
# 双向链的另一端（specs/ 目前没有子目录，无输出属正常）
grep -rn "Parent roadmap → entry" specs/
# 从一条需求一路拉到决策与测试
grep -rn "FR-001" specs/ docs/adr/ tests/
# 状态改 delivered 前的门禁
pnpm test
```

本表与 `tests/` 冲突时**先确认哪个是意图**，再同步两边，不允许长期双轨。涉及排期、资源与上线范围的调整，须找产品与技术负责人确认后再改本表。
