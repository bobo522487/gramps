# 0010. 富文本编辑器选型：TipTap（ProseMirror 封装），正文存 ProseMirror JSON

- **状态**：已接受（**决策**；依赖尚未安装，见§决策 1）
- **日期**：2026-10-27
- **可逆性**：单向门——文档格式一旦进了库、进了已排版的谱书，换编辑器要重排数据（同 [ADR 0003](./0003-tree-storage-ltree.md) 那类门）
- **取代**：[决策索引](./README.md) 待决策 **D-9**（富文本选型）——D-9 自此转为本 ADR 并从待决策表移除，由 `scripts/check-docs.mjs` 的已解决清单执行
- **相关**：[ADR-12（边界是 ProseMirror JSON）](./README.md) · [ADR 0009 §1/§5（依赖只减不增、选型三问）](./0009-dependency-and-runtime-stance.md) · [ADR 0011（`article.plain_text` 的 trigram 检索）](./0011-search-boundary-node-client-article-trgm.md) · [PRD FR-ART-1…5](../prd.md) · [05-data](../architecture/05-data.md) · [技术栈评审 S1-1](../reviews/2026-10-25-linus-stack-review.md)

## 背景

谱文（谱序 / 凡例 / 传记 / 像赞）是 PRD 里唯一需要富文本编辑的功能：FR-ART-2 要求标题、加粗、列表、引用、表格（M1 不含图片），FR-ART-3 要求正文能引用人丁 ID，FR-ART-4 要求停止输入 2 秒后自动保存，FR-ART-5 要求按标题与正文全文检索。

[决策索引](./README.md) 的 ADR-12 定了**边界**：`article.content` 存 ProseMirror JSON，不存 HTML。这里要说清"定了"只到文档为止：**ADR-12 是一份写下来的边界，不是已经落地的数据形状**——今天**没有任何代码读或写 `article.content`**，没有 JSON → `plain_text` 的序列化器，也没有任何一条这个形状的数据存在于生产库。具体用哪个编辑器一直是待决策 **D-9**，`package.json` 里 `tiptap` / `prosemirror` / `lexical` / `slate` 一个都没有。与此同时 `article` 表与 `idx_article_search`（`article.plain_text` 上的 trigram 索引，见 [ADR 0011](./0011-search-boundary-node-client-article-trgm.md)）已经在库里：**表已就绪，边界后面是空的**——这才是本 ADR 要么现在定、要么等谱文立项再定的原因。

这正是最后一次廉价决策的窗口：现在没有任何解析 `article.content` 的业务代码，装什么、不装的代价都还是 0。等到谱文开工再想，就要在"已经有一批谱文写进库"的前提下改文档格式。

## 决策

### 1. 编辑器引擎选 TipTap（ProseMirror 封装），正文存 ProseMirror JSON

`article.content` 存 **ProseMirror 文档 JSON**（承接 ADR-12），渲染、校验、检索都只认这一种形状，不存 HTML 字符串。

**决策 ≠ 现在安装。** 谱文功能立项（有真实的编辑需求、有消费者）之前，`package.json` 里**不得**出现 `tiptap` / `@tiptap/*` / `prosemirror-*` / `lexical` 等编辑器依赖。**编辑器目前尚未安装**，`package.json` 依赖表里没有它们中的任何一个，本 ADR 不新增依赖、不改变任何运行期行为。

理由直接引 [ADR 0009 §1](./0009-dependency-and-runtime-stance.md)：新增运行期依赖必须"替换掉一段自己写的代码"，否则就是"付成本、无消费者"的税。现在没有任何代码解析或渲染 `article.content`，装进来就是没有任何调用方的依赖；它的依赖树（含对 React 适配层的版本约束）只有在谱文立项、真正有消费者时才值得扛，提前扛则是纯粹的付成本。

版本事实：TipTap 当前的稳定线是 **3.x**（本 ADR 写于 2026-10；以 Tiptap 官方发布说明与 npm 上 `@tiptap/core` 的 3.x 版本线为准）。所以"不安装"的理由**不是**"它还不稳定"，而是上面这条——没有消费者（ADR 0009 §1）。

### 2. 按 ADR 0009 §5 的选型三问逐条回答

**① 它替我们编码了什么不变式？**

正文的**结构**由编辑器 schema 约束（哪些块能嵌套、表格单元里能放什么、引用节点必须携带人丁 ID），而不是由字符串正则约束。这带来一条单一事实源：

- **`article.plain_text` 由 `article.content` 派生，不得独立写入。** 二者各写各的，就会出现"检索命中了正文里删掉的句子"。`idx_article_search` 只对 `plain_text` 有意义，所以这条不变式是检索的前提，不是优化。
- 派生规则只在 `lib/article/**` 一处实现（JSON → 纯文本），服务端写入与检索都走它。
- FR-ART-3 的"引用某个人丁"因此是一个有类型的节点，而不是正文里的一段不可校验的文字。

**② 它消灭了哪些特殊分支？**

- 自写 `contenteditable` 的选区、光标、输入法（中文拼音组词）处理；
- 加粗等行内标记的 DOM ↔ 数据双向同步；
- 表格的合并单元格、行内选区、按行列删除；
- 从 Word / 网页粘贴时的 HTML 清洗（schema 直接丢弃不认识的结构，不用另写白名单）。

M1 的 5 种块级排版 + 1 种行内格式确实**用 60 行渲染器也能做**（评审 S1-1 方案 A）。但**渲染**是 60 行，**编辑**不是：上面四条特殊分支是编辑器生态交给我们的东西，自己写会在中文输入法和表格上反复付费。选择这笔支付的时机是谱文立项，不是现在。

**③ 换掉它要改几个文件？**

被约束在 **`lib/article/**` 与单个编辑器组件**两处：

- 一份 schema / 文档类型定义（"ProseMirror JSON" 在这里被理解）；
- 一个客户端编辑器组件（TipTap 只在这里被 import）；
- 一个 server 端序列化器（JSON → `plain_text`、JSON → 渲染树）。

`article.content` 的列类型是 `jsonb`，**任何** ProseMirror 兼容的编辑器（或未来自写的 schema）都能读它，替换时不需要数据迁移。这条约束由 [ADR 0009 §3/ADR-24](./0009-dependency-and-runtime-stance.md) 的口径要求执行者：谱文立项时 `biome.json` 的 `noRestrictedImports` 应把 `@tiptap/*` 限制在这两处，届时与实现同 PR 落地。

### 3. 没有迁移，也没有下坡路要修

诚实写清楚：因为**尚未安装**任何编辑器依赖，本次决策**不需要**数据迁移、不需要 `pnpm remove`、不需要回滚脚本。`article.content` 列本来就存在（`jsonb`），形状不变。与 [ADR 0011](./0011-search-boundary-node-client-article-trgm.md) 保留 `idx_article_search` 是同一件事的两面：**数据侧已经就绪，编辑器侧留给谱文立项**。

## 后果

### 正面

- 单向门后面不再是空的：谱文立项时不必再开一次选型讨论，直接按本文装包。
- "边界 = ProseMirror JSON" 与 "引擎 = TipTap" 分成两层写，**格式可逆性**与**引擎可逆性**从此是两句话，评审时不会混谈。
- `plain_text` 派生自 `content` 这条不变式被写下来，检索与正文不再可能各说各话。
- 现在不为一个未立项的功能扛 30+ 包的传递依赖（ADR 0009 §1）。

### 负面（诚实写）

- TipTap 3.x 是当前稳定线，但大版本的 API 与依赖树仍会继续变；本 ADR 记的是**此刻**的判断（装哪个大版本留给谱文立项时决定），见重估触发条件。
- "决策 ≠ 现在安装"留出了一个空档：在谱文立项前，**没有任何东西能证明这个选择是对的**——没有代码、没有测试、没有真实数据的反馈。接受这个空档，而不是用一个提前安装的依赖来假装验证过。
- 选 TipTap 等于为 M4 的实时协同预付了一部分路线（ProseMirror 的 CRDT 生态最成熟），而协同在 ADR 里明确排除在 M1–M3 之外。如果协同最终不做，这份预付款就浪费了。

### 中性

- 本 ADR 不修改 ADR-12 的正文（已接受的 ADR 不改），只在其外部把"用哪个编辑器"补齐；ADR-12 的索引行改指向本文。
- 本 ADR 不新增依赖、不改 `package.json`、不改任何源文件。
- 依赖禁令由 `tests/docs-consistency.test.ts` 执行：**只要本文写着"尚未安装"，`package.json` 的依赖里就不得出现编辑器包**；谱文立项安装后，同步删掉"尚未安装"这句话，断言随之自然退出（不会拦住真实实现）。

## 放弃的方案

| 方案 | 为什么不够好 |
|---|---|
| 现在就把 TipTap 装上"打底" | 没有消费者就付传递依赖与安全公告的税（ADR 0009 §1）；且装上一个没人用的依赖，会让文档与 `package.json` 的漂移变成常态——正是 04-runtime 里 RHF 那类事故 |
| 自写受限结构化模型（段落数组 + 块类型，评审 S1-1 方案 A） | 渲染 60 行能做，**编辑**不能：中文输入法、选区、表格合并、粘贴清洗四条特殊分支要自己写；只要 M1 的 5 种块不变它就是够的，但 M2 的谱书排版一旦要更多行内格式就要推翻 |
| 选 Lexical | 结构化程度更高，但生态更小、文档更少；1–3 人团队的学习成本是真金白银，而它的主要优势（更强的节点模型、Meta 的工程投入）不在我们 5 种块的需求里 |
| 存 HTML（放弃 ADR-12 的格式边界） | 结构不可校验、不可迁移、不能服务端安全渲染；`plain_text` 的派生失去单一事实源。注意 ADR-12 目前只是文档层面的边界：没有读者、没有写者、也没有迁移需要回退 |
| 存 TipTap 自定义 JSON 而非 ProseMirror JSON | 两者是**两种完全不同的可逆性**（评审 S1-1）：绑定到 TipTap 的内部形状后，换引擎就要改数据 |

## 重估触发条件

1. **TipTap 发布下一个大版本（4.x）**，或依赖树 / React 适配层的约束发生破坏性变化（例如 `@tiptap/react` 要求与当前 React 19 不兼容）：重新评估版本、依赖树与 React 适配层约束，再决定谱文立项时装哪个大版本。
2. **PRD FR-ART-2 的块级需求超出 5 种**（或新增图片/脚注/目录等节点）：`lib/article` 的 schema 设计要重看，可能推翻"TipTap 标准节点够用"这个前提。
3. **M4 实时协同被正式立项**：协同时的文档粒度（段落级 patch 还是整篇覆盖，见评审 S1-1 第 3 点）会反过来决定 `article.content` 的形状，必须与 ADR-0002（无编辑锁）一起重看。
4. **谱文立项但仍不打算上编辑器**（例如先只做只读渲染）：本 ADR 的引擎选择继续挂起，"决策 ≠ 现在安装"保持不变，D-9 也不回到待决策表——决策已经有了，只是还没执行。
