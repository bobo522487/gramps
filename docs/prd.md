## 1. 产品概述

### 1.1 定位

面向**家族修谱场景**的在线谱系编纂平台。一个组织（一个家族或一个修谱工作室）在云端建立「云谱空间」，录入世系、撰写谱文、编排谱书目录。

**M1 只解决「把信息结构化地存下来」。** 呈现（预览、成书、分享）与协作（编辑锁、多人在线）是 M2 之后的事。

### 1.2 目标用户

| 用户 | 特征 | 核心诉求 |
|---|---|---|
| 修谱主事人 | 家族中负责修谱的长辈或热心人，60 后为主 | 把散落在纸质族谱、口述、微信里的信息结构化存下来 |
| 修谱工作室 | 承接多个家族修谱业务的小团队（2–5 人） | 一个账号服务多个客户，数据互不串 |
| 族内协作者 | 各房支的联络人，负责录入本房人丁 | 只改自己那一支，不怕改坏别处 |

### 1.3 价值主张

| 对比对象 | 差异 |
|---|---|
| 纸质族谱 | 可检索、可增量修订、不惧损毁 |
| 通用在线文档 | 原生表达世系关系（父子、配偶、世次、字辈），不是画表格 |
| 本地修谱软件 | 免安装、多人共享同一份数据 |

### 1.4 不做什么

不做社交、不做 DNA 检测、不做家族电商、不做 AI 自动生成族谱内容。产品边界是**记录**，M1 阶段连呈现都不做。

## 2. 术语

| 术语 | 英文标识 | 定义 |
|---|---|---|
| 组织 | `organization` | 隔离单位。一个家族或一个修谱工作室 |
| 云谱空间 | `project` | 组织内的一套族谱资料集合。一个组织可有多个 |
| 谱系 | `lineage` | 一棵世系树。一个云谱空间可有多个 |
| 人丁 | `node` | 谱系中的一个人。含血亲与配偶 |
| 世次 | `generation` | 第几世。始祖为 1 |
| 字辈 | `generation_words` | 用于命名的辈分用字序列 |
| 谱文 | `article` | 独立的文章：谱序、凡例、传记、像赞 |
| 谱书 | `book` | 一本书的元信息与封面配置，**不含正文** |
| 编目 | `book_catalog` | 谱书的目录，引用谱系或谱文 |

**「谱书不含正文」是核心设计**：书的内容由编目引用谱系与谱文构成。改一次谱系，多本书同时更新——这个结构在 M1 就要建对，虽然 M1 还不渲染它。

## 3. 角色与权限

### 3.1 角色

角色只有 4 个，全部在**组织级**。不存在项目级角色。

| 角色 | 说明 | 典型使用者 |
|---|---|---|
| `owner` | 组织所有者，唯一 | 建组织的人 |
| `admin` | 管理员 | 修谱主事人 |
| `editor` | 编辑者 | 各房支联络人 |
| `viewer` | 只读 | 审核者、顾问 |

### 3.2 权限矩阵

| 能力 | owner | admin | editor | viewer |
|---|:--:|:--:|:--:|:--:|
| 查看内容 | ✅ | ✅ | ✅ | ✅ |
| 编辑谱系 / 人丁 | ✅ | ✅ | ✅ | — |
| 撰写谱文 | ✅ | ✅ | ✅ | — |
| 编排谱书 / 编目 | ✅ | ✅ | ✅ | — |
| 删除内容 | ✅ | ✅ | ✅ | — |
| 创建 / 删除云谱空间 | ✅ | ✅ | — | — |
| 邀请成员 | ✅ | ✅ | — | — |
| 修改成员角色 / 移除成员 | ✅ | ✅ | — | — |
| 组织设置 / 停用 | ✅ | — | — | — |
| 转让所有权 | ✅ | — | — | — |

### 3.3 权限实现

代码中用**权限字符串**判断，不直接判角色。角色到权限的映射集中在一处，新增角色不改业务代码。

```typescript
const ROLE_PERMISSIONS = {
  owner:  ['*'],   // 仅 owner 使用通配；包含 org.settings 与转让所有权
  admin:  ['content.read', 'lineage.write', 'article.write', 'book.write',
           'project.write', 'member.invite', 'member.manage'],
  editor: ['content.read', 'lineage.write', 'article.write', 'book.write'],
  viewer: ['content.read'],
} as const;
```

`'*'` 只允许出现在 `owner` 上；权限判断遇到 `'*'` 直接放行。`org.settings` 由 owner 的通配覆盖，不单独列出。

## 4. 信息架构

### 4.1 对象模型

```
组织 organization
├── 成员 / 邀请
└── 云谱空间 project
    ├── 分类 folder（谱系 / 谱文 / 谱书 三棵树）
    ├── 谱系 lineage ── 人丁 node
    ├── 谱文 article
    └── 谱书 book ── 编目 book_catalog
```

### 4.2 导航

| 层级 | URL | 内容 |
|---|---|---|
| L0 | `/dashboard` | 我所属的组织列表 + 最近访问 |
| L1 | `/dashboard/org/[orgSlug]` | 组织概览、成员、设置 |
| L2 | `/dashboard/project/[projectRef]` | 云谱空间首页：谱系 / 谱文 / 谱书 |
| L3 | `/dashboard/project/[projectRef]/lineages/[id]` | 谱系图编辑器 |
| L3 | `/dashboard/project/[projectRef]/articles/[id]` | 谱文编辑器 |
| L3 | `/dashboard/project/[projectRef]/books/[id]/catalog` | 谱书编目三栏 |

`projectRef` 全局唯一；项目页按 `projectRef` + 当前用户解析 scope，不要求在 URL 里重复 `orgSlug`。

`orgSlug` 与 `projectRef` 都是 20 位 `[0-9a-z]` 随机公开 ID，由服务端生成且不可修改；它们只用于定位，不是授权凭证，服务端解析时必须同时按当前用户的成员关系过滤。

公开页面只有营销首页 `/` 与登录/注册；M1 没有匿名业务数据页、分享页或公开 API。

## 5. 功能需求

需求编号规则 `FR-<模块>-<序号>`。每条含验收标准，验收标准是可测的。

### 5.1 FR-AUTH 账号与认证

M1 只支持**邮箱 + 密码**。手机验证码与第三方登录见 §6.2。

M1 **不接入邮件通道**：注册无需等待验证邮件，忘记密码也不能自助找回；邀请通过手动复制的链接完成。

| # | 需求 | 验收标准 |
|---|---|---|
| FR-AUTH-1 | 邮箱 + 密码注册 | 密码 ≥ 8 位含字母数字；注册成功即登录，无需等待验证邮件 |
| FR-AUTH-2 | 邮箱 + 密码登录 | 邮箱与密码正确即可登录；不存在的邮箱与密码错误使用同一文案 |
| FR-AUTH-3 | 会话保持 | 关闭浏览器再打开仍登录；Better Auth 数据库会话 7 天有效、`updateAge` 1 天滑动续期；会话被删除或撤销后立即失效 |
| FR-AUTH-4 | 登出 | 登出后当前会话立即失效，其他设备不受影响 |
| FR-AUTH-5 | 登录失败限流 | 同一来源 + 账号在 15 分钟内失败 10 次后，短时拒绝登录；计数保存在应用进程内，不持久化，多实例下为尽力而为；错误文案统一为「账号或密码错误」 |
| FR-AUTH-6 | 修改密码（登录态） | 验证当前密码；成功后撤销其他设备会话，当前设备保持登录 |

### 5.2 FR-ORG 组织与成员

| # | 需求 | 验收标准 |
|---|---|---|
| FR-ORG-1 | **注册即得默认组织** | 账号创建成功后自动生成 1 个组织，用户为 `owner`，直接可用，不需要额外「创建组织」步骤 |
| FR-ORG-2 | 新建额外组织 | 填名称即可；`slug` 由服务端生成（20 位 `[0-9a-z]` 随机公开 ID），全局唯一且不可修改 |
| FR-ORG-3 | 多组织切换 | 一个账号可属于多个组织；切换组织不重新登录 |
| FR-ORG-4 | 邀请成员 | 生成一次性邀请链接/token，7 天有效，由邀请人手动复制；接受后成为指定角色（不能邀 owner）；不发邮件 |
| FR-ORG-5 | 修改成员角色 | owner/admin 可改；不能把最后一个 owner 降级 |
| FR-ORG-6 | 移除成员 | 移除后该成员立即失去访问权；其创建的内容保留 |
| FR-ORG-7 | 组织设置 | 仅可修改名称；`slug` 是 URL 标识，不可修改；仅 owner 可改 |
| FR-ORG-8 | 组织停用/归档 | `suspended` 状态下写操作返回 `ORG_SUSPENDED`、只读放行；`closed`/`deleted_at` 表示归档并从控制台隐藏。M1 UI 只提供归档入口 |

**FR-ORG-1 的默认值**

| 项 | 规则 |
|---|---|
| `name` | 取邮箱 `@` 前缀，如 `chen@x.com` → `chen`；为空则「我的家族」 |
| `slug` | 20 位 `[0-9a-z]` 随机公开 ID，由数据库默认值生成，全局唯一且不可修改 |
| `role` | `owner` |
| 时机 | 与账号创建**同一事务**，由数据库触发器完成 |

用户不需要理解「组织」这个概念就能开始用——**先可用，再理解**。

### 5.3 FR-PROJ 云谱空间

| # | 需求 | 验收标准 |
|---|---|---|
| FR-PROJ-1 | 创建云谱空间 | 填项目名、姓氏、地区、主题名，设置状态、重要等级与可选备注；姓氏与主题名创建后不可修改；项目名 ≤24 字符；服务端自动生成 20 位 `ref` 作为 URL 第二段 |
| FR-PROJ-2 | 多个云谱空间 | 一个组织可建多个，数量不限 |
| FR-PROJ-3 | 分类管理 | 三种类型（谱系/谱文/谱书）各自独立树，最多 3 层；删除分类不影响其中的内容（变为「未分类」） |

### 5.4 FR-LIN 谱系与人丁

这是产品的核心模块。

| # | 需求 | 验收标准 |
|---|---|---|
| FR-LIN-1 | 创建谱系 | 填名称、姓氏、郡望、字辈；创建后进入空画布 |
| FR-LIN-2 | 录入始祖 | 空谱系上点击「添加始祖」，生成第一个节点，世次 = 1 |
| FR-LIN-3 | 添加配偶 | 在任意血亲节点上添加；配偶不占世次，不参与世系路径 |
| FR-LIN-4 | 添加兄弟 | 在节点上添加同辈；继承父节点，世次相同 |
| FR-LIN-5 | 添加子女 | 在节点上添加子代；世次 +1，可连续添加多个 |
| FR-LIN-6 | 编辑人丁信息 | 姓名、字号、性别、生卒、葬地、行传、自定义字段 |
| FR-LIN-7 | 删除人丁 | 删除节点连带其全部子孙；一次操作作为一组软删，从界面消失（**M1 无恢复界面**） |
| FR-LIN-8 | 移动人丁 | 改挂到另一个父节点；重算该子树世次与路径 |
| FR-LIN-9 | 谱系图交互 | 拖拽平移、滚轮缩放、点击选中、双击编辑；1000 节点下 ≥ 45fps |
| FR-LIN-10 | 按代加载 | 超过 500 节点的谱系默认只渲染前 5 代，向右平移或点按钮每次追加 5 世 |
| FR-LIN-11 | 人丁搜索 | 按姓名模糊搜索，结果定位到画布节点 |
| FR-LIN-12 | 字辈提示 | 录入姓名时按世次提示对应字辈用字 |
| FR-LIN-13 | 世系表视图 | 表格形式按世次列出全部人丁，支持打印视图（不含 CSV / PDF 导出） |

**FR-LIN-7 的删除语义**：M1 采用**软删**（`deleted_at`），不物理删除，但**不提供回收站界面**。误删的恢复由运维在数据库层面完成。

这样取舍的原因：软删是零成本的保险，硬删是不可逆的灾难。家谱数据的一次误删，对一个家族是不可接受的损失。UI 可以后补，数据没了就补不回来。

### 5.5 FR-ART 谱文

| # | 需求 | 验收标准 |
|---|---|---|
| FR-ART-1 | 新建谱文 | 标题 + 类型（像赞/谱序/凡例/传记）+ 富文本正文 |
| FR-ART-2 | 富文本编辑 | 支持标题、加粗、列表、引用、表格（M1 不含图片，见 §6.2） |
| FR-ART-3 | 插入人丁引用 | 正文中可引用某个人丁，存储其 ID（M1 仅存引用，渲染在 M2） |
| FR-ART-4 | 自动保存 | 停止输入 2 秒后保存；显示「已保存」状态 |
| FR-ART-5 | 谱文检索 | 按标题与正文全文检索 |

**FR-ART-4 的并发语义**：M1 无编辑锁，自动保存是 last-write-wins。同一篇谱文被两人同时编辑时，后保存的覆盖先保存的。这是已知限制，见 ADR 0002 / §6.3 缺口 3。

### 5.6 FR-BOOK 谱书与编目

| # | 需求 | 验收标准 |
|---|---|---|
| FR-BOOK-1 | 创建谱书 | 填书名、主题名、姓氏、郡望、卷册、编者、编撰时间 |
| FR-BOOK-2 | 封面配置 | 选模板 ID + 填变量，存为结构化数据（**M1 不做实时预览**，渲染在 M2） |
| FR-BOOK-3 | 编目编辑 | 三栏：左（可引用内容）中（编目树）右（属性） |
| FR-BOOK-4 | 编目引用 | 一条编目只能引用一个谱系或一篇谱文，或都不引用（纯标题） |
| FR-BOOK-5 | 编目排序 | 拖拽排序；支持嵌套（卷 → 章 → 节） |
| FR-BOOK-6 | 章节分区 | 每条编目标记为开篇 / 正文 / 附录 |
| FR-BOOK-7 | 引用完整性 | 被编目引用的谱系/谱文不可删除，提示先移除编目 |
| FR-BOOK-8 | 隐藏条目 | 可标记隐藏，仅存储；M2 渲染时跳过 |

## 6. 范围

### 6.1 M1 包含

账号（邮箱密码）、**注册即得默认组织**、成员与邀请、云谱空间、分类、谱系与人丁（四种新增方式）、谱文、谱书与编目。

### 6.2 M1 不包含

| 项 | 原编号 | 原因 |
|---|---|---|
| 手机号验证码登录 | — | 需要短信服务商，先验证邮箱密码是否够用 |
| 第三方登录（微信 / Google） | — | OAuth 配置与账号合并逻辑，非核心价值 |
| 版式设置 | FR-PROJ-4 | 没有渲染，版式无消费者 |
| **谱书预览与分享** | FR-PREV-1~6 | 渲染引擎是独立工程，M2 做；M1 只保证编目数据正确 |
| **回收站** | FR-TRASH-1~5 | 数据层软删已就位，缺的是 UI；恢复先由运维兜底 |
| **协作编辑锁** | FR-COLLAB-1~6 | 需要锁表 + 心跳 + fencing，M1 用户量下冲突概率低 |
| **媒体上传** | FR-MEDIA-1~5 | 头像、封面图非核心；谱文 M1 也不插图片 |
| 邮件通道 / 自助密码找回 | — | M1 不接入邮件投递；忘记密码只能人工处理 |
| PDF 排版成书 / 导出 | — | 排版引擎与字体授权，M2 单独做 |
| 任何后台任务、定时器 | — | 无必要 |
| OCR 识别老谱 | — | 识别质量不可控 |
| 微信小程序 | — | Web 优先 |
| GEDCOM 导入导出 | — | 用户量不足 |
| 站内信 / 通知中心 | — | 无邮件通道，邀请靠手动复制链接 |
| 客户自助数据导出 | — | 合同 + 手工 `pg_dump` 兜底 |

### 6.3 M1 的已知缺口

砍掉上面这些之后，M1 有 6 个必须承认的缺口：

| # | 缺口 | 影响 | 缓解 |
|---|---|---|---|
| 1 | 看不到成品 | 用户录完不知道长什么样 | 用编目顺序 + 世系表视图给「结构感」；M2 补齐 |
| 2 | 无法分享 | 族人看不到 | 暂用截图 / 导出图片沟通 |
| 3 | 两人同时编辑会互相覆盖 | 数据可能被旧内容覆盖 | 界面提示「建议一人先编辑完」；M2 加锁 |
| 4 | 删了找不回 | 误删需运维介入 | 软删兜底 + 运维手册；M2 加回收站 |
| 5 | 忘记密码无法自助找回 | 只能联系运维人工处理 | 注册时提示妥善保管密码；M2 接入邮件后补找回流程 |
| 6 | 日志保留期外无法逐条追溯修改 | 纠纷或合规审计缺少细粒度记录 | 软删 + PITR/备份兜底；有明确需求时再引入审计表 |

这 6 条要写进销售话术与帮助文档，不能假装不存在。

## 7. 非功能需求

| 类别 | 需求 | 指标 |
|---|---|---|
| 性能 | 内部页面首屏 | TTFB < 400ms，LCP < 2.5s |
| 性能 | 谱系画布 | 1000 节点拖拽 ≥ 45fps |
| 性能 | 保存操作 | p95 < 800ms |
| 容量 | 单组织 | 谱书 ≤ 200，人丁 ≤ 50 万；单谱系 5 万、画布 2000 可见节点（口径见 architecture/05-data §8.5） |
| 容量 | 全平台 | 组织 ≤ 500，人丁总量 ≤ 2000 万 |
| 可用性 | 月度可用率 | ≥ 99.5%（测量手段见 R19；在探针落地前是目标，不是已验证承诺） |
| 恢复 | RPO / RTO | ≤ 1 天 / ≤ 4 小时 |
| 安全 | 跨组织访问 | 必须为 0 |
| 安全 | 密码存储 | Better Auth scrypt；应用不接触哈希，不保存明文 |
| 兼容 | 浏览器 | Chrome / Edge / Safari 最近 2 个大版本 |
| 兼容 | 设备 | 桌面优先；现有控制台含移动端抽屉，但不作为 M1 承诺 |
| 无障碍 | 对比度 | 正文 ≥ 4.5:1 |

## 8. 成功指标

| 指标 | 定义 | 目标（上线 6 个月） |
|---|---|---|
| 激活率 | 注册后 7 天内创建谱系并录入 ≥ 10 人丁 | ≥ 40% |
| 留存 | 次月仍有编辑行为的组织占比 | ≥ 50% |
| 深度 | 单组织人丁数中位数 | ≥ 200 |
| 录入效率 | 单条人丁从点击到保存的中位耗时 | < 15 秒 |
| 质量 | 保存失败率 | < 0.1% |

> 保存失败率 <0.1% 的测量手段见 R19；在服务端 `error.code` / 客户端上报落地前是目标，不是已验证承诺。

**不追的指标**：注册数、DAU、分享次数（M1 没有分享）。修谱是低频高强度场景，DAU 没有意义。
