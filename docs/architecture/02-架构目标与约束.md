# 架构目标与约束

> **回答什么问题**：是什么力量决定了这个架构？用了哪些技术、为什么是它们？放弃了什么？
> **读者**：评估改动的人　**长度上限**：5 页
> **目标 vs 现状**：本文描述当前实现（as-is）与已定的选型结论。目标设计见 [11-需求与实现状态](./11-需求与实现状态.md) 与 [decisions](../decisions/README.md)。

版本号一律以 `package.json` 为准，本文不另立基线表；决策的完整论证在 [decisions](../decisions/README.md) 的对应 ADR 里，本文只给结论与链接。

## 业务目标

编号沿用旧文档，不重新编号——其他文档与 ADR 里引用的 G 编号指的就是这些。

| 编号 | 目标 | 现在靠什么支撑 | 相关文档 |
|---|---|---|---|
| G1 | 一个云谱空间的数据不能被另一个云谱空间读到 | 应用层按成员关系过滤 + `withOrg` 事务内 RLS + 复合外键三层；跨组织换 `orgId` 的查询返回 0 行 | [04-数据视图-数据架构](./04-数据视图-数据架构.md)、[09-安全架构](./09-安全架构.md) |
| G2 | 大组织也能编辑：人丁多、画布同时可见节点多时仍可交互 | 世系用 `ltree` 路径而非递归查询；画布按代渲染窗口限制同屏节点；布局是纯函数 | [04-数据视图-数据架构](./04-数据视图-数据架构.md)、[08-非功能性设计](./08-非功能性设计.md) |
| G3 | 加一个业务实体的成本可控 | 模块化单体 + 垂直切片 + 每张表单一 owner；新增实体按固定清单执行 | [03-逻辑视图-模块设计](./03-逻辑视图-模块设计.md)、[../guides/add-a-feature.md](../guides/add-a-feature.md) |
| G4 | 线上故障可定位 | 结构化日志贯穿 `request_id`；每个错误响应带稳定 `code` | [10-可观测性与运维](./10-可观测性与运维.md) |
| G5 | 基础设施成本与团队规模匹配 | 全托管 Vercel + Neon；零后台任务、零队列、零独立缓存层 | [06-部署视图-部署架构](./06-部署视图-部署架构.md)、[decisions/0005](../decisions/0005-zero-background-jobs.md) |
| G6 | 不为没有消费者的功能预建结构 | 新增表/列必须在 PRD 或 ADR 里有对应条目；已预建的编目引用与 `cover_spec` 有 ADR 支撑 | [decisions/0010](../decisions/0010-rich-text-editor-selection.md)、[12-风险与演进规划](./12-风险与演进规划.md) |

**G 编号的使用方式**：G1–G6 是判断「这个改动值不值得做」的口径，不是里程碑。某个目标现在达没达到，看 [11-需求与实现状态](./11-需求与实现状态.md)，本文件不判断。

## 质量属性

本表只写**属性、场景与判定方式**；具体目标值统一在 [08-非功能性设计](./08-非功能性设计.md) 定义，避免同一数字写两处。

| 属性 | 场景（刺激 → 响应） | 目标值或判定方式 |
|---|---|---|
| 性能 | 打开一个谱系工作区 → 首屏出图，随后交互不阻塞 | 首屏由 RSC 直出，客户端不再瀑布式请求；阈值见 [08-非功能性设计](./08-非功能性设计.md) |
| 可用性 | 单区域故障 → 系统整体不可用 | 没有降级与多活设计；这是显式接受的取舍，见 [12-风险与演进规划](./12-风险与演进规划.md) |
| 可扩展性 | 组织数与人丁数增长 10 倍 → 先坏在哪 | 三个已知先坏点：活动日志无归档、画布同屏节点数、数据库连接数；见 [08-非功能性设计](./08-非功能性设计.md) |
| 安全 | 有人猜到一个公开 ID 或伪造 `orgId` → 被拒 | 非成员与不存在的 ID 一律 404；三层隔离，见 [09-安全架构](./09-安全架构.md) |
| 可维护性 | 有人往单个文件里堆逻辑，或从查询层 import 页面 → CI 变红 | 单文件行数上限、`process.env` 读取位置、依赖方向三条，由 `pnpm arch:check` 与 Biome 拦截 |
| 可运维性 | 一次发布或一次回滚 → 步骤数可控 | 发布 = 合并 `main` 触发构建；回滚 = 重新部署上一版本；没有应用层回滚脚本，见 [06-部署视图-部署架构](./06-部署视图-部署架构.md) |
| 一致性 | 多步写中途失败 → 不留半成品 | 单事务完成，失败整体回滚；没有补偿任务，见 [07-运行视图-关键流程](./07-运行视图-关键流程.md) |

## 约束

### 技术约束

运行时、语言、数据库的版本与放弃的替代见下一节「技术栈（选型结论）」，这里只列**不能碰的规则**。

| 约束 | 具体是什么 | 为什么不能碰 |
|---|---|---|
| 无后台任务 | 不新增队列、定时器、后台消费者 | 部署模型里没有消费者与调度器，见 [decisions/0005](../decisions/0005-zero-background-jobs.md) |
| 无 i18n 框架 | 界面全简体中文 | 单语言产品，引入即增加一层无收益抽象 |
| 单文件 ≤400 行 | `app`/`components`/`lib`/`hooks` 下 | 存量豁免清单只许缩不许涨 |
| `process.env` 只在 `lib/config.ts` 读 | 其余模块向该文件要配置 | 环境变量散落会导致生产漏配无法静态发现 |
| 依赖方向 | 客户端组件不得 import `@/lib/db/*`；`lib/db/**` 不得 import `next/*`；`lib/db/queries/**` 不得 import Actions | 由 Biome `noRestrictedImports` 自动拦截 |

### 合规与数据约束

| 约束 | 具体是什么 |
|---|---|
| 租户数据不出组织 | 家谱含在世人口信息，跨组织泄露是最高等级事故；RLS 是兜底，应用层必须自己过滤 |
| 邮箱只读 | 没有改邮箱入口，邮箱验证关闭 |
| 密码不可逆 | scrypt 存储，应用代码不接触哈希 |
| 业务表软删 | `deleted_at`，查询默认 `isNull`；成员与邀请是硬删除，不可恢复 |
| 无审计表 | `activity_logs` 是产品活动流，不是审计日志；追溯靠软删与 PITR |
| 日志脱敏 | 不记录密码、token、身份证、完整住址 |

### 团队与交付约束

| 约束 | 具体是什么 |
|---|---|
| 团队规模 | 1–3 人全栈，无专职运维、无 DBA |
| 评审能力 | 没有独立评审人，靠 CI 门禁兜底（`docs:check`、`arch:check`、`test:coverage`、迁移漂移检查） |
| 发布节奏 | 允许分钟级发布中断；迁移与业务代码分开提交，先迁移后代码 |
| 托管边界 | 只用 Vercel + Neon 托管能力，不自建数据库、不自建消息中间件 |

## 技术栈（选型结论）

每行的「为什么是它」只写一句结论，完整论证在对应 ADR；版本以 `package.json` 为准。

| 层 | 选型 | 版本 | 为什么是它 | 放弃的替代 |
|---|---|---|---|---|
| 框架 | Next.js App Router | `16.4.3` | 首屏用 RSC 直读数据库，写操作走 Server Action，不需要自建 API 层 | 独立前后端（多一套部署与鉴权边界）、Pages Router（拿不到 RSC） |
| 语言 | TypeScript | `7.0.2`（Go 原生实现） | `strict` + 4 条实测零报错的额外检查；贵开关逐个拒绝并留下报错数（[0012](../decisions/0012-typescript7-compiler-flags.md)） | 关闭严格模式（已证明会在构建时被框架静默写回）、更贵的检查项 |
| 运行时 | Node.js 24 LTS · pnpm 12 | `>=24 <25` · `pnpm@12.15.0` | 与 Vercel 运行时一致；pnpm 的严格 node_modules 让幽灵依赖当场暴露 | npm/yarn（幽灵依赖）、Bun（与平台运行时不一致） |
| 数据库 | PostgreSQL | 18+（CI 用 `postgres:18-alpine`） | 需要 `uuidv7()`、`ltree`、`pg_trgm`、行级安全与非属主角色 | MySQL（无 `ltree`/RLS）、SQLite（无并发写与 RLS） |
| ORM | Drizzle | `drizzle-orm ^0.45.4` · `drizzle-kit ^0.31.11` | SQL 形态的查询构造器，迁移可读可审；事务与 `SET LOCAL` 可控 | Prisma（生成客户端重、难表达 RLS 会话变量）、裸 SQL（无类型） |
| 认证 | 自托管 Better Auth + organization 插件 | `1.7.12` | 数据库会话、组织/成员/邀请模型现成；运行期角色边界清楚（[0007](../decisions/0007-self-hosted-better-auth.md)） | 自建 bcrypt + JWT（会话撤销要自建 `token_version`）、托管 SaaS（数据出境与成本） |
| 客户端数据 | TanStack Query | `^5.104.5` | 只读刷新通道 + 首屏 `dehydrate` 注入；缓存新鲜度集中一处配置 | SWR（能力重叠）、自建缓存 |
| UI 状态 | zustand | `5.0.16` | 只用于谱系工作区的视图状态，不存实体、不 persist | Redux/Jotai（对这个用途过重） |
| 样式与组件 | Tailwind v4 + shadcn/ui（radix-ui） | `tailwindcss 4.3.3` · `radix-ui 1.8.1` | 组件源码进仓库可改；设计令牌集中在 `components/ui` 与 `lib/ui/status.ts` | CSS-in-JS（与 RSC 冲突）、整包组件库（不可控样式） |
| 图与画布 | `@xyflow/react` | `^12.12.0` | 需要可交互的节点画布与自定义布局 | 自绘 SVG（交互成本高）、图表库（不是图编辑场景） |
| 校验 | Zod | `4.6.7` | 表单、URL 参数、API body 统一入口校验，中文消息 | 手写校验、Yup |
| 检查与格式 | Biome | `2.6.3` | 一个工具做 lint + format，且能表达三条依赖方向规则 | ESLint + Prettier（两套配置、无 `noRestrictedImports` 等价能力） |
| 测试 | Vitest + Playwright | `5.0.5` · `1.64.1` | 单测与真实 PostgreSQL 集成测试同栈；E2E 对 production server 跑关键路径 | Jest（ESM/TS 配置成本）、Cypress（跨浏览器与并行更弱） |
| 部署 | Vercel + Neon | `@vercel/functions 3.10.3` | 无状态函数 + 托管 PostgreSQL；不需要常驻进程 | 自建 VM/K8s（1–3 人团队运维不起） |

`postgres 3.4.9`（本地/CI 驱动）与 `pg ^8.23.1`（生产驱动）并存是刻意的：生产要 `attachDatabasePool` 才能在实例冻结时回收连接，本地要 prepared statements。切换条件写在 `lib/db/drizzle.ts` 与 `lib/db/auth-db.ts`。

### 版本与依赖立场

- **版本基线只有一处**：`package.json`。文档不另立基线表，也不写「当前是 N 个依赖」这类汇总数字。
- **依赖只减不增**（[0009](../decisions/0009-dependency-and-runtime-stance.md)）：新增依赖要说明为什么现有能力不够；ORM 升级只走专门 PR，`drizzle-orm` 1.0 单独立项。
- **决策 ≠ 现在安装**（[0010](../decisions/0010-rich-text-editor-selection.md)）：富文本编辑器的格式边界已定（ProseMirror JSON），但 TipTap 及其传递依赖**尚未安装**——决策先于安装是允许的，反过来不行。
- **约束必须有执行者**（[0009](../decisions/0009-dependency-and-runtime-stance.md) §3）：一条规则只有在 lint / CI / 测试 / 迁移之一存在时才算已决策，否则从文档删除。这条规则的具体清单在 [08-非功能性设计](./08-非功能性设计.md) 的 Fitness functions 一节。
- **升级要按「是否改变了可选的设计空间」分类**（[2026-10-25 技术栈评审](../archive/reviews/2026-10-25-linus-stack-review.md) 附录 B）：TypeScript 5.x → 7.0.2 与 Zod 3 → 4 是结构性升级（前者把类型检查从「排队跑」变成「随时跑」，后者把 `z.uuid()` 收紧到 RFC 9562 variant）；`radix-ui` 1.4 → 1.8 与 `lucide-react` 0.x → 1.x 是装饰性升级（用法已收在 `components/ui/` 里，版本对调用方不可见）。
- **「升级到最新稳定」不能替代选型决策**：那一轮 10 项升级里只有 3 项结构性、5 项中性、2 项装饰——前者是维护动作，后者是设计动作，所以本节的「为什么是它」不写成「因为它新」。

## 驱动因素 → 设计决策的映射

每个重要设计都应该能回答「它服务于哪个目标」。

| 驱动因素 | 落到哪个设计 | 记录在哪 |
|---|---|---|
| 跨组织泄露是最高等级事故 | 三层隔离：应用层过滤 + RLS（`app_rw` + `auth.has_org_role`）+ 复合外键 | [decisions/0006](../decisions/0006-rls-isolation.md)、[04-数据视图-数据架构](./04-数据视图-数据架构.md) |
| 小团队没有运维能力 | 零后台任务、零队列；邀请过期靠查询判断而不是定时任务 | [decisions/0005](../decisions/0005-zero-background-jobs.md) |
| 不自建身份系统 | 自托管 Better Auth：数据库会话 + scrypt，不依赖外部 IdP | [decisions/0007](../decisions/0007-self-hosted-better-auth.md)、[09-安全架构](./09-安全架构.md) |
| 写操作必须能复权、不能靠客户端 | 全部写走 Server Action；只保留只读 Route Handler 做刷新与健康检查 | [decisions/0008](../decisions/0008-read-only-route-handlers.md)、[05-接口与集成设计](./05-接口与集成设计.md) |
| 首屏要快、交互要跟手 | RSC 首屏直读 + TanStack Query 缓存；新鲜度只由 `staleTime` 决定 | [decisions/0013](../decisions/0013-next-react-runtime-layer.md)、[07-运行视图-关键流程](./07-运行视图-关键流程.md) |
| 世系要能快速取子树 | 邻接表 + `ltree` 物化路径，移动子树是改路径 | [decisions/0003](../decisions/0003-tree-storage-ltree.md)、[04-数据视图-数据架构](./04-数据视图-数据架构.md) |
| 删除必须可追溯但不能做回收站 UI | 业务表软删且永久保留，成员与邀请硬删 | [decisions/0004](../decisions/0004-soft-delete-forever.md)、[12-风险与演进规划](./12-风险与演进规划.md) |
| 不做编辑锁 | 冲突概率低于锁成本，靠提示与事务兜底 | [decisions/0002](../decisions/0002-no-edit-lock.md)、[07-运行视图-关键流程](./07-运行视图-关键流程.md) |
| 依赖准入 | 新依赖要过准入标准，不为「可能用到」提前引入 | [decisions/0009](../decisions/0009-dependency-and-runtime-stance.md)、本文「版本与依赖立场」 |

完整决策清单与可逆性见 [decisions 索引](../decisions/README.md)；技术栈结论与放弃的替代见本文上一节。
