## 业务目标

编号沿用旧文档，不重新编号——其他文档与 ADR 里引用的 G 编号指的就是这些。

| 编号 | 目标 | 现在靠什么支撑 | 相关文档 |
|---|---|---|---|
| G1 | 一个云谱空间的数据不能被另一个云谱空间读到 | 应用层按成员关系过滤 + `withOrg` 事务内 RLS + 复合外键三层；跨组织换 `orgId` 的查询返回 0 行 | [04-数据视图-数据架构](./04-数据视图-数据架构.md)、[09-安全架构](./09-安全架构.md) |
| G2 | 大组织也能编辑：人丁多、画布同时可见节点多时仍可交互 | 世系用 `ltree` 路径而非递归查询；画布按代渲染窗口限制同屏节点；布局是纯函数 | [04-数据视图-数据架构](./04-数据视图-数据架构.md)、[08-非功能性设计](./08-非功能性设计.md) |
| G3 | 加一个业务实体的成本可控 | 模块化单体 + 垂直切片 + 每张表单一 owner；新增实体按固定清单执行 | [03-逻辑视图-模块设计](./03-逻辑视图-模块设计.md)、[../guides/add-a-feature.md](../guides/add-a-feature.md) |
| G4 | 线上故障可定位 | 结构化日志贯穿 `request_id`；每个错误响应带稳定 `code` | [10-可观测性与运维](./10-可观测性与运维.md) |
| G5 | 基础设施成本与团队规模匹配 | 全托管 Vercel + Neon；零后台任务、零队列、零独立缓存层 | [06-部署视图-部署架构](./06-部署视图-部署架构.md)、[decisions/0005](../decisions/0005-zero-background-jobs.md) |
| G6 | 不为没有消费者的功能预建结构 | 新增表/列必须在 PRD 或 ADR 里有对应条目；已预建的编目引用与 `cover_spec` 有 ADR 支撑 | [decisions/0010](../decisions/0010-rich-text-editor-selection.md)、[13-风险与演进规划](./13-风险与演进规划.md) |

**G 编号的使用方式**：G1–G6 是判断「这个改动值不值得做」的口径，不是里程碑。某个目标现在达没达到，看 [实现状态](../implementation-status.md)，本文件不判断。

## 质量属性

本表只写**属性、场景与判定方式**；具体目标值统一在 [08-非功能性设计](./08-非功能性设计.md) 定义，避免同一数字写两处。

| 属性 | 场景（刺激 → 响应） | 目标值或判定方式 |
|---|---|---|
| 性能 | 打开一个谱系工作区 → 首屏出图，随后交互不阻塞 | 首屏由 RSC 直出，客户端不再瀑布式请求；阈值见 [08-非功能性设计](./08-非功能性设计.md) |
| 可用性 | 单区域故障 → 系统整体不可用 | 没有降级与多活设计；这是显式接受的取舍，见 [13-风险与演进规划](./13-风险与演进规划.md) |
| 可扩展性 | 组织数与人丁数增长 10 倍 → 先坏在哪 | 三个已知先坏点：活动日志无归档、画布同屏节点数、数据库连接数；见 [08-非功能性设计](./08-非功能性设计.md) |
| 安全 | 有人猜到一个公开 ID 或伪造 `orgId` → 被拒 | 非成员与不存在的 ID 一律 404；三层隔离，见 [09-安全架构](./09-安全架构.md) |
| 可维护性 | 有人往单个文件里堆逻辑，或从查询层 import 页面 → CI 变红 | 单文件行数上限、`process.env` 读取位置、依赖方向三条，由 `pnpm arch:check` 与 Biome 拦截 |
| 可运维性 | 一次发布或一次回滚 → 步骤数可控 | 发布 = 合并 `main` 触发构建；回滚 = 重新部署上一版本；没有应用层回滚脚本，见 [06-部署视图-部署架构](./06-部署视图-部署架构.md) |
| 一致性 | 多步写中途失败 → 不留半成品 | 单事务完成，失败整体回滚；没有补偿任务，见 [07-运行视图-关键流程](./07-运行视图-关键流程.md) |

## 约束

### 技术约束

| 约束 | 具体是什么 | 为什么不能碰 |
|---|---|---|
| 运行时 | Node.js 24 LTS + pnpm 12 | 与 Vercel 运行时和 CI 对齐 |
| 语言 | TypeScript 7（Go 原生实现），`strict` 开启 | `strict` 被删会静默降级，见 [decisions/0012](../decisions/0012-typescript7-compiler-flags.md) |
| 数据库 | PostgreSQL 18 或更高 | 主键依赖 `uuidv7()`，树依赖 `ltree` |
| 无后台任务 | 不新增队列、定时器、后台消费者 | 部署模型里没有消费者与调度器，见 [decisions/0005](../decisions/0005-zero-background-jobs.md) |
| 无 i18n 框架 | 界面全简体中文 | 单语言产品，引入即增加一层无收益抽象 |
| 单文件 ≤400 行 | `app`/`components`/`lib`/`hooks` 下 | 存量豁免清单只许缩不许涨 |
| `process.env` 只在 `lib/config.ts` 读 | 其余模块向该文件要配置 | 环境变量散落会导致生产漏配无法静态发现 |
| 依赖方向 | 客户端组件不得 import `@/lib/db/*`；`lib/db/**` 不得 import `next/*`；`lib/db/queries/**` 不得 import Actions | 由 Biome `noRestrictedImports` 自动拦截 |

### 合规与数据约束

| 约束 | 具体是什么 |
|---|---|
| 租户数据不出组织 | 家谱含在世人口信息，跨组织泄露是最高等级事故；RLS 是兜底，应用层必须自己过滤 |
| 邮箱只读 | 没有改邮箱入口，邮箱验证关闭 |
| 密码不可逆 | scrypt 存储，应用代码不接触哈希 |
| 业务表软删 | `deleted_at`，查询默认 `isNull`；成员与邀请是硬删除，不可恢复 |
| 无审计表 | `activity_logs` 是产品活动流，不是审计日志；追溯靠软删与 PITR |
| 日志脱敏 | 不记录密码、token、身份证、完整住址 |

### 团队与交付约束

| 约束 | 具体是什么 |
|---|---|
| 团队规模 | 1–3 人全栈，无专职运维、无 DBA |
| 评审能力 | 没有独立评审人，靠 CI 门禁兜底（`docs:check`、`arch:check`、`test:coverage`、迁移漂移检查） |
| 发布节奏 | 允许分钟级发布中断；迁移与业务代码分开提交，先迁移后代码 |
| 托管边界 | 只用 Vercel + Neon 托管能力，不自建数据库、不自建消息中间件 |

## 驱动因素 → 设计决策的映射

每个重要设计都应该能回答「它服务于哪个目标」。

| 驱动因素 | 落到哪个设计 | 记录在哪 |
|---|---|---|
| 跨组织泄露是最高等级事故 | 三层隔离：应用层过滤 + RLS（`app_rw` + `auth.has_org_role`）+ 复合外键 | [decisions/0006](../decisions/0006-rls-isolation.md)、[04-数据视图-数据架构](./04-数据视图-数据架构.md) |
| 小团队没有运维能力 | 零后台任务、零队列；邀请过期靠查询判断而不是定时任务 | [decisions/0005](../decisions/0005-zero-background-jobs.md) |
| 不自建身份系统 | 自托管 Better Auth：数据库会话 + scrypt，不依赖外部 IdP | [decisions/0007](../decisions/0007-self-hosted-better-auth.md)、[09-安全架构](./09-安全架构.md) |
| 写操作必须能复权、不能靠客户端 | 全部写走 Server Action；只保留只读 Route Handler 做刷新与健康检查 | [decisions/0008](../decisions/0008-read-only-route-handlers.md)、[05-接口与集成设计](./05-接口与集成设计.md) |
| 首屏要快、交互要跟手 | RSC 首屏直读 + TanStack Query 缓存；新鲜度只由 `staleTime` 决定 | [decisions/0013](../decisions/0013-next-react-runtime-layer.md)、[07-运行视图-关键流程](./07-运行视图-关键流程.md) |
| 世系要能快速取子树 | 邻接表 + `ltree` 物化路径，移动子树是改路径 | [decisions/0003](../decisions/0003-tree-storage-ltree.md)、[04-数据视图-数据架构](./04-数据视图-数据架构.md) |
| 删除必须可追溯但不能做回收站 UI | 业务表软删且永久保留，成员与邀请硬删 | [decisions/0004](../decisions/0004-soft-delete-forever.md)、[13-风险与演进规划](./13-风险与演进规划.md) |
| 不做编辑锁 | 冲突概率低于锁成本，靠提示与事务兜底 | [decisions/0002](../decisions/0002-no-edit-lock.md)、[07-运行视图-关键流程](./07-运行视图-关键流程.md) |
| 依赖准入 | 新依赖要过准入标准，不为「可能用到」提前引入 | [decisions/0009](../decisions/0009-dependency-and-runtime-stance.md)、[11-技术选型与决策记录](./11-技术选型与决策记录.md) |

完整决策清单与可逆性见 [11-技术选型与决策记录](./11-技术选型与决策记录.md) 与 [decisions 索引](../decisions/README.md)。
