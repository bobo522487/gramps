## 术语补充

00 章的术语表已经覆盖了业务与数据层的核心词。以下是读代码时容易卡住的实现层词汇：

| 术语 | 含义 |
|---|---|
| `ltree` | PostgreSQL 扩展类型，用点分标签表示树路径（如 `a.b.c`）。`node.path` 用它存物化路径，子树查询写成 `<@`，祖先查询写成 `@>` |
| 物化路径 | 把从根到当前节点的路径直接存在行里，读子树不用递归查询；代价是移动节点要重写整棵子树的路径 |
| 部分唯一索引 | 带 `WHERE` 条件的唯一索引。本仓库用它表达「同一组织只能有一个 owner」「同一组织同一邮箱只能有一个待处理邀请」 |
| 复合外键 | 多列外键，用来表达「子行的父行必须属于同一组织/同一谱系」。它是租户隔离的第三层，不是可选的整洁性优化 |
| `SET LOCAL` | 只在当前事务内生效的 `SET`。`withOrg` 用它切到 `app_rw`；会话级 `SET` 会污染连接池里的连接 |
| RLS 策略里的 `auth.has_org_role` | 策略调用的函数，按当前会话用户与目标组织查成员关系。策略本身不写裸子查询 |
| `AsyncLocalStorage` | Node 的请求级上下文容器。`lib/server/request-context.ts` 用它携带 `request_id` 与 `user_id`，日志不需要逐层传参 |
| Flight | React Server Component 的传输协议。`dehydrate` 的首屏数据就是随 Flight 响应一起下发的 |
| HydrationBoundary | TanStack Query 的边界组件，把服务端注入的缓存交还给客户端 `QueryClient` |
| Fitness function | 可自动执行的架构约束检查。清单在 [08-非功能性设计](./08-非功能性设计.md)，那里也是唯一来源 |
| 豁免清单 | `scripts/check-file-size.mjs` 里允许超过 400 行的文件列表。规则是**只许缩小**，新增条目要评审 |
