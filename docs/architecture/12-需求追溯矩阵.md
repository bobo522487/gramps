模块划分与所有权见 [03-逻辑视图-模块设计](./03-逻辑视图-模块设计.md)；接口形态与错误语义见 [05-接口与集成设计](./05-接口与集成设计.md)。**本文不判断需求是否完成**——状态只有一个来源，见矩阵的「状态」列。

## 编号体系

- 需求编号沿用 PRD 的 `FR-<模块>-<序号>`，**本文件不新增、不改写、不重排编号**。
- 覆盖范围是 PRD §5 的六个模块（`FR-AUTH` / `FR-ORG` / `FR-PROJ` / `FR-LIN` / `FR-ART` / `FR-BOOK`）。
- PRD §6.2 明确排除在 M1 之外的编号（`FR-PROJ-4` 版式设置、`FR-PREV-1` 谱书预览分享、`FR-COLLAB-1` 编辑锁、`FR-TRASH-1` 回收站、`FR-MEDIA-1` 媒体上传）**不进矩阵**：它们没有可追溯的代码，进矩阵只会制造空行。
- 「接口」列写真实存在的入口：Server Action 名、Route Handler 路径、RSC 页面或迁移里的数据库对象。写不出来的说明该需求没有实现入口，写 `—`。
- 「状态」列**只放链接**，判定与说明全部在 [实现状态](../implementation-status.md)（模块级）与其 §3（FR 级差异）。

## 覆盖缺口

矩阵里「测试文件 = `—`」的需求按模块归组。**注意区分两种缺口**：`FR-ART-*` / `FR-BOOK-*` 的缺口不是「缺测试」而是「缺实现入口」——补测试之前先要有代码；判定见 [实现状态](../implementation-status.md) §2、§3。

| 模块 | 缺口需求 | 缺的是什么 |
|---|---|---|
| `content` | FR-ART-1、FR-ART-2、FR-ART-3、FR-ART-4 | 缺实现入口，因此没有任何层级的测试；`search-boundary` 只锁索引边界，不覆盖 FR-ART-5 的检索行为 |
| `publishing` | FR-BOOK-1、FR-BOOK-2、FR-BOOK-3、FR-BOOK-5、FR-BOOK-6、FR-BOOK-8 | 缺实现入口；FR-BOOK-4 / FR-BOOK-7 只有集成测试锁住数据库约束，没有应用层测试 |

已有入口但**只有单测、没有集成测试**的需求（下一层风险）：

| 模块 | 需求 | 缺的是 |
|---|---|---|
| `auth` | FR-AUTH-5 | 只有进程内滑窗的单测，没有「真实登录请求被限流」的集成测试 |
| `lineage` | FR-LIN-10、FR-LIN-11、FR-LIN-12、FR-LIN-13 | 只有布局 / 谓词 / 常量的单测，没有「超过 500 人时首屏只渲染 5 世」这类行为测试，也没有 E2E |
| `organization` | FR-ORG-3 | 只有 401 与 DTO 契约的集成测试，没有「切换组织后数据范围变化」的测试 |

E2E 只覆盖两条路径（注册→建项目→谱系→录入→检查器→侧栏；邀请→登出→登录→接受邀请），其余需求没有端到端保护。
