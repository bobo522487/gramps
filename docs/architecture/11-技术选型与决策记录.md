# 技术选型与决策记录

> **回答什么问题**：用了什么技术、为什么是它？做过哪些不可逆或代价高的决策？还有什么没定？
> **读者**：开发 · 架构评审　**长度上限**：5 页

## 技术栈

| 层 | 选型 | 版本 | 为什么是它 | 放弃的替代 |
|---|---|---|---|---|
| 框架 | Next.js App Router | `16.4.3` | 首屏用 RSC 直读数据库，写操作走 Server Action，不需要自建 API 层 | 独立前后端（多一套部署与鉴权边界）、Pages Router（拿不到 RSC） |
| 语言 | TypeScript | `7.0.2`（Go 原生实现） | `strict` + 4 条实测零报错的额外检查；贵开关逐个拒绝并留下报错数（[0012](../decisions/0012-typescript7-compiler-flags.md)） | 关闭严格模式（已证明会在构建时被框架静默写回）、更贵的检查项 |
| 运行时 | Node.js 24 LTS · pnpm 12 | `>=24 <25` · `pnpm@12.15.0` | 与 Vercel 运行时一致；pnpm 的严格 node_modules 让幽灵依赖当场暴露 | npm/yarn（幽灵依赖）、Bun（与平台运行时不一致） |
| 数据库 | PostgreSQL | 18+（CI 用 `postgres:18-alpine`） | 需要 `uuidv7()`、`ltree`、`pg_trgm`、行级安全与非属主角色 | MySQL（无 `ltree`/RLS）、SQLite（无并发写与 RLS） |
| ORM | Drizzle | `drizzle-orm ^0.45.4` · `drizzle-kit ^0.31.11` | SQL 形态的查询构造器，迁移可读可审；事务与 `SET LOCAL` 可控 | Prisma（生成客户端重、难表达 RLS 会话变量）、裸 SQL（无类型） |
| 认证 | 自托管 Better Auth + organization 插件 | `1.7.12` | 数据库会话、组织/成员/邀请模型现成；运行期角色边界清楚（[0007](../decisions/0007-self-hosted-better-auth.md)） | 自建 bcrypt + JWT（会话撤销要自建 `token_version`）、托管 SaaS（数据出境与成本） |
| 客户端数据 | TanStack Query | `^5.104.5` | 只读刷新通道 + 首屏 `dehydrate` 注入；缓存新鲜度集中一处配置 | SWR（能力重叠）、自建缓存 |
| UI 状态 | zustand | `5.0.16` | 只用于谱系工作区的视图状态，不存实体、不 persist | Redux/Jotai（对这个用途过重） |
| 样式与组件 | Tailwind v4 + shadcn/ui（radix-ui） | `tailwindcss 4.3.3` · `radix-ui 1.8.1` | 组件源码进仓库可改；设计令牌集中在 `components/ui` 与 `lib/ui/status.ts` | CSS-in-JS（与 RSC 冲突）、整包组件库（不可控样式） |
| 图与画布 | `@xyflow/react` | `^12.12.0` | 需要可交互的节点画布与自定义布局 | 自绘 SVG（交互成本高）、图表库（不是图编辑场景） |
| 校验 | Zod | `4.6.7` | 表单、URL 参数、API body 统一入口校验，中文消息 | 手写校验、Yup |
| 检查与格式 | Biome | `2.6.3` | 一个工具做 lint + format，且能表达三条依赖方向规则 | ESLint + Prettier（两套配置、无 `noRestrictedImports` 等价能力） |
| 测试 | Vitest + Playwright | `5.0.5` · `1.64.1` | 单测与真实 PostgreSQL 集成测试同栈；E2E 对 production server 跑关键路径 | Jest（ESM/TS 配置成本）、Cypress（跨浏览器与并行更弱） |
| 部署 | Vercel + Neon | `@vercel/functions 3.10.3` | 无状态函数 + 托管 PostgreSQL；不需要常驻进程 | 自建 VM/K8s（1–3 人团队运维不起） |

`postgres 3.4.9`（本地/CI 驱动）与 `pg ^8.23.1`（生产驱动）并存是刻意的：生产要 `attachDatabasePool` 才能在实例冻结时回收连接，本地要 prepared statements。切换条件写在 `lib/db/drizzle.ts` 与 `lib/db/auth-db.ts`。

## 版本与依赖立场

- **版本基线只有一处**：`package.json`。文档不另立基线表，也不写「当前是 N 个依赖」这类汇总数字。
- **依赖只减不增**（[0009](../decisions/0009-dependency-and-runtime-stance.md)）：新增依赖要说明为什么现有能力不够；ORM 升级只走专门 PR，`drizzle-orm` 1.0 单独立项。
- **决策 ≠ 现在安装**（[0010](../decisions/0010-rich-text-editor-selection.md)）：富文本编辑器的格式边界已定（ProseMirror JSON），但 TipTap 及其传递依赖**尚未安装**——决策先于安装是允许的，反过来不行。
- **约束必须有执行者**（[0009](../decisions/0009-dependency-and-runtime-stance.md) §3）：一条规则只有在 lint / CI / 测试 / 迁移之一存在时才算已决策，否则从文档删除。这条规则的具体清单在 [08-非功能性设计](./08-非功能性设计.md) 的 Fitness functions 一节。

## 待决策项

待决策清单的唯一来源是 [decisions 索引](../decisions/README.md) 的「待决策」一节，本文件不复制它的问题描述与两种说法。当前仍未决的是这四条：

| 编号 | 主题 | 与本架构文档的关系 |
|---|---|---|
| D-4 | 关系模型 | 单 `parent_id` 无法表达过继 / 兼祧 / 入赘，直接影响 [04-数据视图](./04-数据视图-数据架构.md) 的树结构与 [03-逻辑视图](./03-逻辑视图-模块设计.md) 的领域模型 |
| D-6 | 数据生命周期 | 软删永存与删除权/保留期冲突，影响 [09-安全架构](./09-安全架构.md) 的合规现状 |
| D-10 | 表单栈 | 扁平表单模型挡住人丁自定义字段与编目树，影响 [03-逻辑视图](./03-逻辑视图-模块设计.md) 的模块边界 |
| D-11 | 登录限流 | 进程内计数 vs 共享存储，影响 [09-安全架构](./09-安全架构.md) 威胁建模里的限流绕过 |

已解决的编号（D-1 / D-2 / D-3 / D-5 / D-7 / D-8 / D-9）在索引里单列并指向对应 ADR，不再属于待决策。决策落定后要做两件事：写一篇 ADR，并从待决策表里删掉那一行——**不要让待决策表变成第二个决策清单**。
