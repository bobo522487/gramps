### 11.1 从指标到场景（新增）

上表的每一条都是**度量**，但缺了三个要素：**谁触发、在什么条件下、期望什么响应**。缺了这三样，指标无法驱动设计决策，也无法暴露指标之间的矛盾。

一个对比：

| 指标写法 | 场景写法 |
|---|---|
| 性能（画布）：1000 节点 ≥ 45fps | 修谱主事人（**来源**）在 5000 人丁的谱系上（**环境**）拖拽画布（**刺激**）时，画布（**制品**）保持流畅（**响应**），帧率 ≥ 45fps 且首帧 < 100ms（**度量**） |

差别不在措辞。场景里的「5000 人丁」会立刻推出一个设计问题：**这 5000 个节点是全部传到浏览器，还是按代取窗口？** 指标写法里这个问题不会出现——所以「1000 节点 45fps」和「组织 50 万人丁」可以并列存在而无人觉得矛盾。

**建议补全的场景清单**（每条对应一个真实设计决策）：

| ID | 场景要点 | 推出的设计 |
|---|---|---|
| QA-PERF-1 | 5000 人丁谱系拖拽，≥45fps，首帧 <100ms | 按代渲染窗口 + 纯函数布局 |
| QA-PERF-2 | 保存一个人丁，p95 < 800ms 且不随谱系规模退化 | 单事务写入 + 子树重算上限 |
| QA-PERF-3 | 打开谱系详情页，TTFB < 400ms（含上下文解析与首屏数据） | 请求级单事务 + 上下文合并查询 |
| QA-AVAIL-1 | 单实例故障，错误率 < 0.5%，恢复 < 30s | 无状态 + 健康探针 + 错误预算 |
| QA-SEC-1 | 持 A 组织会话请求 B 组织谱系，返回 404 且不泄露存在性 | RLS + 应用层过滤 + 复合外键 |
| QA-DATA-1 | 误删 200 人子树，15 分钟内整组恢复，零丢失 | 软删 + 同事务时间戳 + runbook |
| QA-MAINT-1 | 新增一个实体，改动 ≤5 个源文件，CI 全绿 | 垂直切片 + [add-a-feature 清单](../guides/add-a-feature.md) |
| QA-PRIV-1 | 数据主体要求删除个人信息，30 天内完成物理删除 | 数据分级 + 保留期 + 硬删路径（当前不成立，R18） |

上表是 §11 指标的判定场景；场景与证据是一套东西，不再并列两套指标。
