# Feature Specification: 谱文编辑器 Word 化与常用格式

**Feature Branch**: `003-article-editor-wordlike`（仅目录名；本规格目录与 git 分支名相互独立）
**Created**: 2026-11-03
**Status**: Draft

**Input**: User description: "Optimize the 谱文 (article) text editor to feel Word-like, and add common formatting. Design system: default recommended — keep existing 云谱 tokens; do NOT vendor Guizang/AGPL themes. Ribbon toolbar + paper canvas + mini page previews; add bold/italic/underline, lists, text align; keep paragraph/h1/h2, fonts/sizes, images, undo/redo; still no color/line-height/tables/blockquote/alt/captions, no template suite (FR-042), no export/share/publish."

本规格只描述「要什么、为什么、怎么验收」，不含实现方案（编辑器引擎、组件拆分、存储与序列化细节）——这些在后续 `/speckit-plan` 与执行计划里决定。

**与 [002 谱文录入与多页编辑](../002-article-authoring/spec.md) 的关系**：002 已交付谱文管理、三区编辑器、多页、配图、自动保存与标题检索。本规格是其上的**行为增强**：优化编辑区观感与常用格式能力，并**修订/取代** 002 的 **FR-031**（原先禁止加粗/斜体/下划线/列表等）。002 其余条款（保存、权限、多页、图片三档宽度、模板套用排除 FR-042、导出排除等）除非本规格明文修订，否则继续有效。

## Clarifications

### Session 2026-11-03（specify 阶段默认裁决）

> 以下裁决由 `/speckit-specify` 按用户意图 + 002 已交付状态作出；若后续 `/speckit-clarify` 改口，以 clarify 记录为准。

- **Q: 设计体系选哪套？** A: **默认推荐——沿用云谱既有控制台视觉语言与令牌**（同一套背景、边框、字色、圆角与间距节奏）。MUST NOT 引入第三方谱系产品主题包或复制其样式资源（含已知 AGPL 许可的外来设计包）。理由：产品一致性优先；外来包许可与品类都不匹配。
- **Q: 「Word 化」要做到什么程度？** A: 只做到**必要表面**：分组图标工具栏、纸张感编辑区、页条缩成迷你纸页预览。不做 File/开始 菜单条、不做沉浸式全屏退出控制台、不做模板库 UI。
- **Q: 002 FR-031 怎么处理？** A: 本规格用新的格式要求**修订并取代** FR-031 中「禁止加粗/斜体/下划线/项目符号」的禁令；文字颜色、行距、表格、引用块、图片 alt/图注等仍禁止（见本规格范围边界）。
- **Q: 对齐是段落对齐还是整页对齐辅助线？** A: **段落文字对齐**（左/中/右）。「对齐基线 / 版式对齐辅助」仍属模板套用，继续由 002 FR-042 / SC-011 排除。
- **Q: 列表含几档？** A: 无序列表与有序列表各一种；不做多级大纲样式库、不做任务清单勾选。
- **Q: 页缩略图要不要真实缩略截图？** A: **不要**全页 DOM 缩略图；迷你纸页上可用文字片段或简化示意即可，目标是「认得出第几页、当前页在哪」，不是所见即所得预览引擎。

### Session 2026-11-03（clarify 轮）

- **Q: 当没有选中任何文字时，用户点击加粗、斜体或下划线，编辑器应该怎样表现？** → A: **与 Word 保持一致**：无选区时切换「随后输入生效」的行内样式状态（pending mark）；之后键入的文字带上该样式；再点同一按钮可关闭。不把整段已有文字一次性套上，也不在无选区时完全无反应。
- **Q: 查看者打开谱文时，格式工具栏应该完全不显示，还是显示但全部禁用？** → A: **完全不显示**：查看者界面 MUST NOT 出现格式工具栏及其他写作用控件（含「立即保存」、插图上传入口等）；只读阅读已排版正文与纸张/页条观感。
- **Q: 迷你纸页预览上的文字片段，应该反映尚未保存的草稿，还是只显示上次成功保存的内容？** → A: **当前页用本地草稿（含未保存）；其他页用各自最新已知内容**（已加载的本地草稿，否则上次成功保存的快照）。不要求为未加载页伪造实时缩略；仍不是整页 DOM/位图引擎。
- **Q: 无序/有序列表是否允许通过缩进变成嵌套子列表，还是本期只做严格单层列表？** → A: **严格单层**：仅一种无序与一种有序列表；MUST NOT 提供 Tab/「增加缩进」嵌套子列表，也 MUST NOT 提供多级大纲样式库。
- **Q: 加粗、斜体、下划线等常用快捷键是否必须作为本期验收项？** → A: **不纳入必须验收**：鼓励支持 Ctrl/Cmd+B/I/U 等，有则更好；无快捷键不阻塞本期完成。格式主路径以工具栏验收为准。

## User Scenarios & Testing *(mandatory)*

> 故事描述的是相对 002 已交付编辑器的**增量**。每个故事可独立验收。

### User Story 1 - 在纸张感编辑区里用分组工具栏排版一段谱序 (Priority: P1)

一位习惯用 Word 写谱序的编辑者打开已有谱文。他希望编辑区看起来像一张白纸放在浅色桌面上，上方有按功能分组的图标工具栏，能立刻加粗标题里的关键词、把某段居中、给条目加项目符号，而不用离开控制台壳层。

**Why this priority**: 「看起来像在写文档 + 常用格式够用」是本规格的核心价值；没有纸张感与分组工具栏，Word 化名不副实；没有加粗/列表/对齐，格式增强不成立。

**Independent Test**: 打开任意可写谱文 → 确认编辑区为居中纸张、工具栏分组可见 → 对选中文字执行加粗、斜体、下划线、左/中/右对齐、无序/有序列表 → 停止输入后出现「已保存」→ 刷新后格式仍在。

**Acceptance Scenarios**:

1. **Given** 我以编辑者打开一篇谱文，**When** 进入编辑器，**Then** 编辑区呈现浅色桌面背景上的白色纸面（有页边距与轻微阴影），桌面宽度下纸面大致接近 A4 可读宽度并水平居中；界面仍包在既有控制台框架内，没有「退出全屏 / 沉浸模式」入口。
2. **Given** 编辑器已打开，**When** 我查看正文上方工具栏，**Then** 看到按组排列的图标控件，至少覆盖：撤销/重做｜段落样式（正文/一级/二级标题）｜字体与字号｜列表｜对齐｜插图；组与组之间有分隔，但没有「文件 / 开始」类菜单栏，也没有第二套产品级 Ribbon 皮肤。
3. **Given** 我选中一段文字，**When** 依次点加粗、斜体、下划线，**Then** 选区立即呈现对应样式；再次点击可取消；刷新后样式仍在。
4. **Given** 光标在某段或选中若干段，**When** 我点左对齐 / 居中 / 右对齐，**Then** 该段文字按所选对齐显示，并在保存后保持。
5. **Given** 光标在某段，**When** 我点无序列表或有序列表，**Then** 该段变为对应单层列表项；可再点同一按钮退出列表；编号/项目符号在刷新后仍正确；无法通过缩进得到嵌套子列表。
6. **Given** 我使用既有段落样式、宋体/黑体/楷体、三档字号、插图三档宽度与撤销/重做，**When** 与新格式混用，**Then** 既有能力全部仍可用，且撤销/重做覆盖新旧格式操作。

### User Story 2 - 用迷你纸页预览快速认页与切页 (Priority: P2)

一篇多页谱文的右侧（或既有页条位置）不再只是冷冰冰的序号块；每页看起来像一张迷你纸，能瞥见一点文字片段，用户点一下就能跳到那一页。

**Why this priority**: 强化「在写一本书」的心智，但不阻塞格式与纸张主路径；可在主路径之后独立打磨。

**Independent Test**: 打开 ≥3 页的谱文 → 页条显示迷你纸页 → 在当前页打字后迷你纸片段跟上本地草稿 → 当前页高亮可辨 → 点击另一页完成切换且不丢未保存提示语义（沿用 002 切页先保存规则）。

**Acceptance Scenarios**:

1. **Given** 一篇至少 3 页的谱文，**When** 我查看页条，**Then** 每页呈现为迷你纸页预览（允许文字片段或简化示意），**不是**整页真实渲染缩略图。
2. **Given** 当前在第 2 页，**When** 我查看页条，**Then** 第 2 页的迷你纸与其他页有明确区分（如描边/背景差），且页序仍从 1 连续可读。
3. **Given** 我在第 1 页改了字，**When** 我点击第 3 页迷你纸，**Then** 仍遵守 002 的切页前保存规则：成功则进入第 3 页，失败则提示并停留。
4. **Given** 我在当前页输入尚未保存的新句，**When** 我看该页迷你纸，**Then** 片段反映本地草稿（含未保存）；其他页片段为其最新已知内容（已加载草稿或上次保存），不必为未加载页实时生成。

### User Story 3 - 查看者只读，且看不到模板/导出等禁入入口 (Priority: P1)

查看者打开同一篇谱文，能阅读已排版内容（含加粗、列表、对齐与纸张布局），但不能改格式；任何人在本规格范围内都看不到模板库、导出、分享、发布或外来主题皮肤入口。

**Why this priority**: 权限与范围边界与 002 一致，格式增强不得打开越权或范围漂移的口子。

**Independent Test**: 查看者账号打开含新格式的谱文 → 格式工具栏与写作用控件均不出现 → 直接调用写入被拒；界面无模板/导出/分享/发布入口。

**Acceptance Scenarios**:

1. **Given** 我是查看者，**When** 打开一篇含加粗与列表的谱文，**Then** 我能看到排版效果与纸张/页条观感，但格式工具栏及其他写作用控件（含立即保存、插图入口）MUST NOT 显示；正文不可编辑。
2. **Given** 任意角色打开编辑器，**When** 巡视界面，**Then** 不存在版式库/套用模板/对齐辅助线、导出、分享、发布入口（含灰色「即将开放」），与 002 FR-042 / FR-041 / SC-011 一致。
3. **Given** 无权限用户猜测地址访问，**When** 尝试打开或写入，**Then** 服务端按「不存在」处理，不泄露资源是否存在。

### Edge Cases

- **空选区点格式按钮**：对「整段生效」的操作（对齐、列表、段落样式）作用于当前段落。对「选区生效」的行内样式（加粗/斜体/下划线）：**无选区时切换随后输入的 pending 状态**（与 Word 一致）——工具栏显示开/关，随后键入文字带上该样式，再点取消；MUST NOT 在无选区时把当前整段已有文字一次性套上或取消；仅开启 pending、尚未键入新字时，保存结果 MUST NOT 凭空多出不可见格式残片。
- **粘贴外部 HTML/Word 内容**：保留文字与段落结构；允许落入本规格白名单内的格式（加粗/斜体/下划线/单层列表/对齐/标题层级）；仍丢弃颜色、行距、表格、外链样式等未开放能力；嵌套列表粘贴后 MUST 压成单层列表（或等价扁平项），不得保留多级缩进结构（在 002 FR-013 基础上扩展白名单，而非全盘保留外部样式）。
- **列表与标题混用**：标题样式与列表互斥时，后点的样式胜出，且结果可撤销；不得出现无法用工具栏清掉的残缺标记。
- **列表嵌套**：本期无嵌套；Tab / 增加缩进 MUST NOT 产生子列表。
- **窄屏**：工具栏可换行或收纳，但本规格列出的格式能力 MUST NOT 缺失；纸面可缩小但仍居中可读；仍留在控制台框架内。
- **只读与保存失败**：查看者（只读）下格式工具栏与写作用控件 MUST NOT 显示（非禁用可见）；保存失败时编辑者未提交的格式改动保留在编辑区，顶栏不得显示「已保存」（沿用 002）。
- **旧文兼容**：002 时期保存的、不含新标记的正文打开后 MUST 正常显示；新格式保存后再打开 MUST 不丢。
- **迷你纸页片段来源**：当前页跟本地草稿（含未保存）；其他页用最新已知内容；空页可用空白/页码示意，不报错。

## Requirements *(mandatory)*

### Functional Requirements

#### 编辑器观感（Word 化必要表面）

- **FR-001**（P0）：谱文编辑区 MUST 呈现「浅色桌面 + 白色纸面」：纸面有可感知页边距与轻微阴影，在桌面宽度下大致接近 A4 可读宽度并水平居中；MUST NOT 做成沉浸式脱离控制台的全屏写作壳。
- **FR-002**（P0）：正文上方 MUST 提供**分组图标工具栏**（Ribbon 风格的分组，而非第二套产品菜单 Ribbon），分组至少包括：撤销/重做｜段落样式｜字体/字号｜列表｜对齐｜插图；组间 MUST 有分隔；MUST NOT 提供「文件 / 开始 / 插入」等菜单式顶栏。
- **FR-003**（P0）：编辑器 MUST 继续留在既有控制台框架（含侧栏导航与项目壳）内；MUST NOT 新增「退出沉浸 / 全屏写作」类会离开该壳的模式。
- **FR-004**（P0）：视觉 MUST 沿用云谱既有控制台设计令牌与组件气质（同一套表面色、边框、字色、焦点与禁用态）；MUST NOT 引入或vendoring 第三方谱系产品主题/皮肤（含 AGPL 外来设计包）。
- **FR-005**（P1）：页条 MUST 升级为**迷你纸页预览**（可显示文字片段或简化示意），当前页可辨；MUST NOT 依赖整页 DOM/位图缩略引擎。当前页的文字片段 MUST 反映本地草稿（含尚未保存的改动）；其他页 MUST 使用各自最新已知内容（已加载的本地草稿，否则上次成功保存的内容）；MUST NOT 要求为尚未加载的页伪造实时预览。
- **FR-006**（P0）：002 的三区结构（分类树、编辑区、页条）与顶栏职责（返回、标题、保存状态、「立即保存」）MUST 保持；本规格只增强编辑区与页条观感及工具栏，MUST NOT 为模板库重开第四区。

#### 格式能力（修订 002 FR-031）

- **FR-007**（P0）：用户 MUST 能对选中文字施加或取消**加粗、斜体、下划线**；三种样式可叠加；状态 MUST 在工具栏上可辨（开/关）。无文字选区时，点击上述按钮 MUST 切换「随后输入生效」的样式状态（与 Word 一致）：之后键入的文字带上该样式，再点同一按钮关闭；MUST NOT 因此改写当前段已有文字。
- **FR-008**（P0）：用户 MUST 能将当前段落设为**无序列表**或**有序列表**，并再操作退出列表；列表在保存与重新打开后 MUST 保持。列表 MUST 为严格单层：MUST NOT 支持缩进嵌套子列表，MUST NOT 提供「增加/减少缩进」类嵌套控件。
- **FR-009**（P0）：用户 MUST 能将段落文字设为**左对齐、居中、右对齐**；对齐结果 MUST 保存并在只读视图中可见。
- **FR-010**（P0）：002 已交付且仍须保留的能力：段落与两级标题、系统内置字体（宋体/黑体/楷体）、三档字号（约 14/16/19px 语义档）、正文插图及三档宽度、撤销/重做（覆盖文字与本规格新增格式）。
- **FR-011**（P0）：**取代 002 FR-031**：自本规格生效起，002 FR-031 中「MUST NOT 提供加粗、斜体、下划线、项目符号」不再适用；改由本规格 FR-007…FR-009 与 FR-012 约束。002 文档可在后续文档同步中标注「部分条款由 003 修订」，但不要求本规格回合改写 002 全文。
- **FR-012**（P0）：本期 MUST NOT 提供：文字颜色、行距、表格、引用块（blockquote）、图片替代文字（alt）、图注、多级大纲样式库、嵌套/多级列表、任务清单。
- **FR-013**（P0）：粘贴外部内容时，MUST 保留纯文字与段落结构，并允许落入本规格开放白名单的格式；MUST 丢弃未开放样式（颜色、行距、表格、外部主题等），避免把 Word 全套样式带进正文。

#### 范围边界与既有约束

- **FR-014**（P0）：模板套用整套能力仍按 002 **FR-042** / **SC-011** 排除：版式库、套用即重排、版式占位、对齐基线、自定义模板等 MUST NOT 交付，也 MUST NOT 留灰色入口。（本规格的「段落对齐」不是版式对齐辅助。）
- **FR-015**（P0）：导出、分享、发布仍按 002 FR-041 排除；编辑器内 MUST NOT 新增此类入口。
- **FR-016**（P0）：保存、切页、权限、组织隔离、图片生命周期等行为 MUST 继续遵守 002 对应条款（含按页保存、查看者只读、服务端鉴权）；本规格不得削弱这些约束。
- **FR-017**（P0）：新格式标记 MUST 随页内容一起保存与还原；重新打开后加粗/斜体/下划线/列表/对齐/标题层级 MUST 与保存前一致，不得被压平成无结构纯文本。
- **FR-018**（P0）：查看者打开谱文时，格式工具栏及其他写作用控件（含「立即保存」、插图上传入口等）MUST NOT 显示；MUST NOT 仅以禁用态保留可见写入入口。只读用户仍可看到已排版正文与纸张/迷你纸页观感。
- **FR-019**（P2）：系统 MAY 提供常用键盘快捷键（如加粗/斜体/下划线的 Ctrl/Cmd+B/I/U）；快捷键**不是**本期必须验收项——有则更好，无则不阻塞完成。格式能力的验收主路径 MUST 以分组工具栏为准。

### Key Entities

- **格式标记（Inline / Block Marks）**：施加在正文上的可保存样式——行内（加粗、斜体、下划线）与块级（段落样式、列表、对齐）。属于谱文页正文结构的一部分，不是独立业务表实体。
- **纸面编辑区（Paper Canvas）**：编辑区的呈现形态（桌面背景 + 白纸），不改变「谱文页」数据实体本身。
- **迷你纸页（Page Chip Preview）**：页条上每页的轻量预览表象，对应既有「谱文页」实体，不引入新的缩略图存储；片段来源为当前页本地草稿、其他页最新已知内容。
- 其余实体（谱文、谱文页、图片、分类、云谱空间、编目引用）沿用 002 定义。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：从未用过本增强的编辑者，在无培训情况下 5 分钟内完成「打开谱文 → 加粗一处 → 建一个列表 → 一段居中 → 看到已保存」，成功率 ≥90%。
- **SC-002**：对含新格式的一页执行保存并刷新，格式还原一致率 100%（加粗/斜体/下划线/列表/对齐/标题/字体字号/图片宽度）。
- **SC-003**：桌面宽度下，首屏即可辨认「纸面编辑区 + 分组工具栏」；抽测用户中 ≥80% 在无提示下能指出工具栏分组与纸面边界。
- **SC-004**：页条迷你纸页在 ≥3 页样本中，用户能在 3 秒内说出当前页码并成功切到另一页（仍遵守切页保存规则）。
- **SC-005**：界面巡检中，模板库/套用/对齐基线/导出/分享/发布入口出现次数为 0（含灰色占位）；外来主题皮肤入口为 0。
- **SC-006**：查看者界面 100% 不出现格式工具栏与写作用控件，且无法通过界面或直接写入改动格式；越权访问仍按「不存在」处理。
- **SC-007**：窄屏下本规格列出的格式能力可达率 100%（允许换行/收纳，不允许缺失）；主路径操作（加粗、列表、对齐）从可见到生效 ≤2 次点击。
- **SC-008**：002 回归：自动保存、多页、插图三档宽度、撤销/重做在启用新格式后仍满足 002 对应成功标准，不得回退。

## Assumptions

- **基线**：002-article-authoring 已在主干交付；本规格增量建立在现有三区编辑器、按页自动保存与插图通道之上，不重做谱文列表/分类/建文流程。
- **FR-031 修订**：用户明确要求放开加粗/斜体/下划线、项目符号与有序列表、左中右对齐；这与 002 clarify 时「全部后置」的历史裁决不同，以**本规格（更新意图）为准**。颜色/行距/表格/引用/alt/图注仍后置。
- **设计默认**：用户已选择「default recommended」设计路线——沿用云谱既有令牌；明确拒绝 vendoring 外来 Guizang/AGPL 设计包（品类与许可均不合适）。规格层只约束「同一套视觉语言」，不点名实现库。
- **Word 化边界**：追求「必要表面像在写 Word 文档」，不是复刻 Microsoft Word 或任何第三方谱软件的完整 Ribbon/模板生态。
- **字号语义**：继续以「小 / 常规 / 大」三档面对用户；约 14/16/19px 为既有实现口径，属观感参考而非本规格新开的自由字号。
- **对齐措辞**：SC-011 / FR-042 所禁的是**版式对齐辅助**；本规格「段落左右中对齐」不视为违反 SC-011。
- **非目标（确认不做）**：模板/版式套用（仍 002 FR-042）、导出/分享/发布、人丁正文引用、正文全文检索、协同编辑锁、离线草稿库、图片裁剪与自由缩放、AI 写作。
- **权限模型**：沿用四角色与 `article.write`；本规格不改变谁能写谱文。
- **数据形态**：新格式仍是页正文结构的一部分，不单独引入用户可运营的「样式资源库」实体。
- **快捷键**：本期不把快捷键矩阵纳入完成定义（clarify Q5）；实现阶段可顺带接上浏览器常见绑定，但不为此单独开验收门禁。
- **窄屏工具栏形态**：允许换行或收纳（Edge Cases），具体交互组件拆分留待 `/speckit-plan`，不阻塞规格验收口径。
