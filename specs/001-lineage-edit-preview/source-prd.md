# PRD-家谱谱系编辑与实时预览

# PRD：家谱谱系编辑与实时预览（本产品）

> 版本：v0.1（草案）　|　状态：待评审　|　参考样本：大谱师 Maker《谱系录编与实时预览》演示视频
> 编写原则：**参考而非照搬**。本文档定义"本产品应成为什么"，以参考样本中验证过的核心价值为基线，按 Linus 哲学、最佳实践与简洁原则做减法与重构。

---

## 0. 文档概述

### 0.1 背景

参考样本"大谱师 Maker"是一款中文家谱数字编辑软件，其演示展示了"录入世系关系与人物生平 → 实时预览成谱"的主线，以及项目概览、创建谱系、节点录入、关系挂接、房系管理、偏好设置、导出/发布等模块。

本产品**不照搬**该样本的全部功能，而是提炼其真正解决的用户问题，并以更克制的方式实现。

### 0.2 设计原则（Linus 哲学 + 最佳实践 + 简洁）

1. **解决真实问题，而非想象中的问题。** 修谱人的核心痛点只有一条：*把世系关系与人物生平录进去，并立刻看到"成谱"的样子*。所有需求以此为标尺，不服务该主线的一律后置或删除。
2. **好品味（Good Taste）。** 能用一种机制解决的，绝不引入第二种；能在默认中解决的，不让用户配置。
3. **默认优于配置。** 参考样本中"完整/简化/空段"三模式字段显隐、大量工具栏按钮，本质是"用配置掩盖没有给出好默认"。本产品改为：给出一套合理默认，仅保留最少的可选扩展。
4. **能不加就不加。** 统计仪表盘、性别比例饼图、签字、收藏夹、合并等，对"编出一本谱"无直接贡献，明确裁剪（见 §11）。
5. **实时预览即"所见即所得"。** 这是样本被验证过的核心价值，作为产品第一原则保留并强化。
6. **导出是终点。** 录入与预览最终要落到"可带走的谱书"，导出/分享为 P0 能力。

### 0.3 范围

- **范围内**：谱系管理、成员节点录入、关系与房系建模、实时预览、导出。
- **范围外（本期不做）**：统计仪表盘、多端小程序协同、在线发布/印刷对接、权限细分、社交分享、AI 智能家谱等。均列入 §11 裁剪清单与待确认。

## 1. 用户与场景

### 1.1 目标用户（基于参考样本合理推断 + 简化）

| 角色 | 描述 | 依据 |
| --- | --- | --- |
| **修谱负责人（核心用户）** | 家族/宗亲指定的谱书主编，未必是专业谱师，但承担主要录入与定稿工作 | 样本教程定位"新手零基础"；项目含"负责人"字段 |
| **参与录入者（次要）** | 协助补全各房各支人物信息的家族成员 | 样本出现"集体传成""操作日志"多用户痕迹 |

> 【待确认】是否区分"专业谱师"与"普通家族成员"两类体验；是否面向机构（宗亲会/祠堂）采购（影响权限与协作深度）。

### 1.2 核心场景（精简为 4 条主线）

- **S1 搭骨架**：负责人新建一个谱系，确定姓氏/堂号/起点先祖，建立首节点。
- **S2 录成员**：逐代录入人物，通过"加子女/配偶/兄弟"或挂接建立关系，填写生平关键信息。
- **S3 看成谱**：录入时中部世系图与右侧信息卡实时刷新，随时确认版式与内容。
- **S4 出成果**：将谱系导出为可保存/打印/分享的谱书文件。

> 说明：样本中的"项目概览仪表盘、字辈分析、性别比例图"等**不作为主线场景**，归为后置增强（§11）。

## 2. 功能需求

优先级约定：**P0 必须有**｜**P1 应有（首版可简）**｜**P2 增强（后置）**

### F1 谱系（项目）管理 — P0

- **F1.1** 新建谱系：弹窗录入最小字段集——`谱系名称*`（限长 24 字）、`姓氏*`、`所属分类`（默认"默认分类"，可新建）、`地区`（默认"中国"）。
  - *设计决策*：相对样本 7 字段（含上源名、源祖另号、原住等），本产品**砍掉非主线必填项**，仅保留搭骨架必需；其余作为节点可选属性，不前置到创建环节。
- **F1.2** 打开/切换谱系；**F1.3** 删除谱系（二次确认）。
- *依据*：样本 00:39「创建谱系」弹窗；00:18 项目概览含多谱系列表。

### F2 成员节点录入 — P0

- **F2.1** 新增首节点：录入`姓名`、`谱名`、`世序(默认1)`、`称谓`、`备注`。
  - *依据*：样本 01:03「新增首节点」弹窗。
- **F2.2** 在谱系图中增删节点：`添加子女`、`添加配偶`、`添加兄弟/姐妹`、`添加节点`。
  - *依据*：样本中 Alt+B/P/N/M 快捷键与底部按钮组（01:03、02:09）。
- **F2.3** 信息卡（人物卡）字段——**核心集（P0）**：`姓名`（含字/号/讳/别名/曾用名）、`性别`、`世代/字辈`、`出生日期`、`出生地`、`在世/已故`、`卒葬日期`、`卒葬地`、`生平/传记`、`备注`。
  - *设计决策*：样本信息卡含 15+ 字段（文化程度、职业、人生简历、卒葬记述、使用字、行字、谱系注说等）。本产品将**文化程度/职业/人生简历等归为 P2 可选扩展**，首版只保"录得清一本谱"的最小集，避免首屏过载。
  - *依据*：样本 02:09、02:16 右侧信息卡字段。

### F3 关系与房系建模 — P0/P1

- **F3.1 关系类型（核心）**：`父子`（含**嗣/继子**）、`配偶`、`同胞（兄弟/姐妹）`。
  - "挂接"机制：可将已有节点挂接为当前人的`子女 / 嗣(继)子 / 配偶`，并选择目标父节点。
  - *依据*：样本 01:44、02:16「挂接」弹窗（子女/嗣子/配偶 + 按姓名/性别/世代/父亲选择）。
- **F3.2 房系（分支）归类 — P1**：将节点归入`房系`（如"文煃位下世系""翔公房系"），支持房系名称与分房节点管理。
  - *依据*：样本 03:15「房系」弹窗。*设计决策*：房系是中国家谱刚需结构，保留但仅做最小 CRUD，不做复杂分支图。

### F4 实时预览 — P0（产品第一原则）

- **F4.1** 中部画布渲染**世系图**（按世代分列：第一代/第二代/第三代…），随录入即时更新。
- **F4.2** 右侧信息卡随选中节点同步显示/编辑，编辑即预览。
  - *依据*：样本标题"实时预览"；02:16 字幕"每条数据录完的视觉效果已经完成了"；多帧对照世系图与信息卡同步。
- *设计决策*：预览即"所见即所得"，不做单独的"预览模式"开关——编辑态即预览态，符合简洁原则。

### F5 导出 — P0

- **F5.1** 将当前谱系导出为**可保存/打印/分享的谱书文件**（具体格式【待确认】：PDF / 印刷版式 / 在线链接）。
  - *依据*：样本编辑器顶部常驻"导出""生成""发布"按钮（02:09），但演示未展开完整流程。
- *设计决策*：首版聚焦"导出一份完整谱书"，不内置"发布到小程序/在线印刷"等链路（归 §11）。

### F6（明确不做，见 §11）

统计仪表盘、字辈/性别分析图、偏好设置三模式、签字、收藏夹、合并、多端小程序登录、在线发布。

## 3. 界面交互

### 3.1 整体布局（以样本验证过的三栏为基线，简化工具栏）

```
┌──────────────┬───────────────────────────┬──────────────┐
│ 左：谱系树    │ 中：世系图画布（实时）      │ 右：人物信息卡 │
│ - 我的谱系    │  - 世代分列节点             │  - 核心字段   │
│ - 房系        │  - 选中高亮                │  - 编辑即预览 │
│ - 新建/打开   │  - 底部：加子女/配偶/兄弟   │              │
└──────────────┴───────────────────────────┴──────────────┘
       顶部工具栏（极简）：新建谱系 | 导出 | （更多：房系/设置）
```

- *设计决策*：样本顶部含 合并/统计/收藏夹/谱系管理/导出/签字/生成/发布/预览 等近 10 个按钮；本产品**收敛为"新建谱系 + 导出 + 更多"**，降低零基础用户认知负荷。
- *依据*：样本 02:09、02:16 编辑器三栏结构（左导航/中画布/右信息卡）。

### 3.2 关键交互

- **新增节点**：按钮（底部）+ 快捷键（P1 增强，至少保留 子女/配偶/兄弟/添加节点）。*依据*：样本快捷键体系 Alt+B/P/N/M（01:03）。
- **挂接关系**：弹窗内搜索目标人 → 选关系类型（子女/嗣子/配偶）→ 保存。*依据*：样本 01:44、02:16。
- **删除节点**：弹窗二次确认，明确提示级联删除。*依据*：样本 02:16「删除」警示"同时删除其所有子女及关系"。
- **字段录入**：文本/日期/单选（性别、在世/已故）等原生控件；日期支持"选择或输入"。*依据*：样本 02:16 信息卡。

## 4. 数据需求

### 4.1 实体与关系（最小模型）

- **Pedigree（谱系）**：id、名称、姓氏、分类、地区、创建时间、负责人。
- **Person（成员节点）**：id、谱系id、姓名、谱名、性别、世代/字辈、世序、在世状态、出生日期、出生地、卒葬日期、卒葬地、生平/传记、备注、父节点id、房系id。
- **Relationship（关系）**：类型枚举 = `父子`(含嗣子) / `配偶` / `同胞`；支持一对多（一人多子女、多配偶）。
- **Branch（房系）**：id、谱系id、房系名称、关联节点列表。

### 4.2 字段约束

- 姓名：必填；谱系名称：必填、限长 24。
- 性别、在世状态：枚举（男/女；在世/已故）。
- 日期：支持"选择或输入"（样本支持农历/公历混排，【待确认】是否需农历）。

### 4.3 数据规模

- *依据*：样本出现"进度数 399""总人数 41"。
- 目标：首版支持**单谱系数千节点**流畅渲染与导出；万级以上列为 P2 性能目标。*【待确认】实际最大规模与并发。*

### 4.4 数据归属与便携

- 谱系数据应可本地保存/导出，**用户拥有完整所有权**（Linus：数据不能锁死在厂商）。*【待确认】存储形态（本地文件 / 云端账户）。*

## 5. 权限角色（最小集）

> 样本暗示多人协作（负责人、操作日志、集体传成），但本期不深做协作。

| 角色 | 权限 | 说明 |
| --- | --- | --- |
| **所有者** | 全部（建/改/删/导出） | 修谱负责人 |
| **编辑者** | 录入与修改，不可删库 | 参与录入的家族成员 |
| **查看者** | 只读预览与导出 | 家族其他成员审阅 |

- *设计决策*：仅 3 角色，不做字段级细粒度权限（样本未演示，且违背简洁）。
- *【待确认】* 是否需要账户体系支撑多角色；是否本期就做协作或后置。

## 6. 异常处理

| 场景 | 处理策略 | 依据 / 说明 |
| --- | --- | --- |
| **删除节点** | 二次确认弹窗，明确"将同时删除其所有子女及关系" | ✅ 样本 02:16 已演示，直接沿用 |
| **必填项缺失** | 提交时阻断并高亮字段，提示文案就近显示 | ⚠️ 样本仅见 `*` 标记，未演示报错样式【待确认】 |
| **关系冲突/循环** | 挂接时校验辈分（如配偶不可为直系祖先）；阻止形成环 | ❌ 样本未演示【待确认】校验规则 |
| **重名节点** | 允许重名（同姓名不同人常见），以节点 id 区分；提示但不阻断 | 【设计决策】 |
| **导出失败/大文件** | 给出失败原因与重试；超大数据分卷或异步 | 【待确认】 |
| **断网/本地丢失** | 本地自动保存草稿，恢复时可续编 | 【设计决策，最佳实践】 |

## 7. 非功能需求

- **N1 实时性**：录入到预览刷新延迟 \< 200ms（核心卖点）。
- **N2 性能**：单谱系 1000 节点时世系图滚动/导出无明显卡顿；目标 5000 节点可用。
- **N3 易用性**：零基础用户无需培训，依据引导 10 分钟内完成"建谱系→录 3 代→预览"。
- **N4 可移植/所有权**：导出格式开放，数据可脱离本产品长期保存。
- **N5 可靠性**：编辑过程本地自动存盘，异常退出不丢数据。
- **N6 跨端（P2）**：桌面为主；小程序/Web 查看为后置，不阻塞首版。

## 8. 验收标准

- **AC-F1**：新建谱系填写名称+姓氏可成功创建并进入编辑器；名称超 24 字被拦截。
- **AC-F2**：可新增首节点；可通过"加子女/配偶/兄弟"或挂接建立关系；信息卡核心字段可保存并回显。
- **AC-F3**：挂接可选择关系类型（子女/嗣子/配偶）与目标父节点并保存成功。
- **AC-F4**：在世系图中新增/修改/删除节点后，中部图与右侧卡在 200ms 内同步更新。
- **AC-F5**：导出可生成一份包含完整世系与人物信息的谱书文件，内容与实际录入一致。
- **AC-F6（删除）**：删除含子女的节点时弹窗明确提示级联删除，确认后其子节点与关系一并移除。
- **AC-N**：1000 节点谱系导出耗时、预览刷新延迟达到 N1/N2 指标（具体阈值【待确认】）。

## 9. 待确认问题

1. **品牌与产品名**：本产品命名与品牌归属（参考样本涉"大谱师 Maker/聚脉/紫脉/采家谱"，关系未明）。
2. **存储与账户**：数据本地文件还是云端账户？是否需登录/多端同步？
3. **导出格式**：首版导出 PDF / 印刷版式 / 在线链接 哪一种或多种？是否需排版版式（欧式/苏式吊线图）？
4. **日期体系**：是否必须支持农历（样本出现"一九六一年四月"等农历表述）？
5. **关系完整性**：除 子女/嗣子/配偶/同胞 外，是否需 过继/兼祧/养亲 等；嗣子在图谱上是否 distinct 渲染？
6. **规模与性能阈值**：实际最大节点数、导出耗时与预览延迟的量化验收线。
7. **协作深度**：本期是否做多角色实时协作，还是仅单人 + 后期导入。
8. **房系复杂度**：房系是否仅需"名称+节点归类"，还是需要分支树/统谱层级。
9. **信息卡字段边界**：被裁剪的 文化程度/职业/人生简历 等，是否确有用户强需求（决定 P2 范围）。
10. **缺失信息说明**：样本为顺滑教程，**未演示**导出完整流程、必填校验报错样式、关系冲突拦截、账户/登录、统计模块实际交互；上述均以上方【待确认】标注，未臆造业务规则。

## 10. 设计决策记录（本产品 vs 参考样本）

| 参考样本功能 | 本产品决策 | 理由（Linus / 简洁） |
| --- | --- | --- |
| 创建谱系 7 字段（上源名/源祖另号/原住…） | 收敛为 4 必需 + 其余后置 | 搭骨架只需最小集，其余是节点属性 |
| 信息卡 15+ 字段全展开 | 核心 10 字段 + P2 可选 | 首屏过载，违背零基础易用 |
| 偏好设置三模式（完整/简化/空段） | 删除，给一套好默认 | "用配置掩盖没给好默认" |
| 顶部 \~10 个工具栏按钮 | 收敛为 新建+导出+更多 | 降低认知负荷 |
| 项目概览仪表盘（性别饼图/字辈分析） | 裁剪，后置 P2 | 对"编出谱"无直接贡献 |
| 签字 / 收藏夹 / 合并 | 裁剪 | 非主线，可无 |
| 在线发布 / 小程序协同 | 裁剪，后置 | 首版聚焦"录→预览→导出"闭环 |
| 实时预览 | **强化**，编辑即预览，无独立预览开关 | 样本被验证的核心价值 |

## 11. 已裁剪需求清单（明确不做 / 后置）

- **裁剪（本期不做）**：统计仪表盘、字辈/性别分析图、偏好设置三模式、签字、收藏夹、节点合并、在线发布、小程序扫码登录、多端实时协作。
- **后置（P2）**：文化程度/职业/人生简历等扩展字段、万级节点性能优化、Web/小程序查看端、AI 智能家谱、印刷对接。

> 裁剪原则：凡不直接服务于"录入世系 → 实时预览 → 导出谱书"主线的，一律后置或删除；确需时再以最小成本补回。
